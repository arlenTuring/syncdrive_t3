# 部署機 34 操作說明

部署機：`34.80.84.224`（GCP instance `syncdrive-t3`，zone `asia-east1-a`）。
所有指令都在 **Mac 上、`syncdrive_t3` 資料夾裡**執行，前提是 gcloud 已登入。

## 最常用的兩個

```bash
./deploy/vm.sh sync      # 更新程式碼：34 拉 GitHub 最新 main → 重建部署 → 升級儀表板資料
./deploy/vm.sh restart   # 重啟前端＋後端（不重建、不換版本）
```

- **有新程式碼要上 34** → `sync`。要先合併進 GitHub 的 `main`，34 拉的是 `main`。
- **只是想重開服務**（卡住、改了 `.env` 之類）→ `restart`。

兩個指令最後都會自動跑健康檢查，看到「通過 39 項，失敗 0 項」就是好的。
`sync` 部署後健康檢查沒過時，會**自動回滾**到上一個健康版本。

## 全部指令

| 指令 | 做什麼 |
|---|---|
| `./deploy/vm.sh sync` | 拉最新 main → 重建部署 → 升級儀表板資料 |
| `./deploy/vm.sh sync --no-deploy` | 只拉程式碼＋升級儀表板資料，不重建 |
| `./deploy/vm.sh update` | 34 上 `git pull` → 重建部署（不動儀表板資料） |
| `./deploy/vm.sh restart` | 重啟前端＋後端 |
| `./deploy/vm.sh restart backend` | 只重啟後端（`web`＝前端；`postgres`／`redis`／`mosquitto`；`all`＝全部） |
| `./deploy/vm.sh status` | 目前程式碼版本、最後健康版本、各容器狀態 |
| `./deploy/vm.sh logs` | 後端最近 200 行 log；`logs web` 看前端；加 `-f` 持續追（Ctrl+C 結束） |
| `./deploy/vm.sh health` | 只跑健康檢查 |
| `./deploy/vm.sh check` | 檢查儀表板存的查詢是否為新版（`uses_schedule` 應全為 `f`）＋訂單筆數 |
| `./deploy/vm.sh rollback` | 回到上一個健康版本 |
| `./deploy/vm.sh ssh` | 直接登入 34 |
| `./deploy/vm.sh` | 顯示指令說明 |

## 常見情境

**上線新功能**
```bash
git pull origin main        # Mac 先拿到最新的腳本
./deploy/vm.sh sync
./deploy/vm.sh status       # 確認容器都是 healthy、版本是剛剛那個
```

**畫面怪怪的、服務沒反應**
```bash
./deploy/vm.sh logs         # 先看後端 log 有沒有錯
./deploy/vm.sh restart      # 重啟前後端
```

**新版上去有問題，想退回**
```bash
./deploy/vm.sh rollback
```

**已登入 34 時，直接在 34 上更新**
```bash
cd /opt/syncdrive_t3 && sudo ./deploy/deploy.sh --pull
```

## 注意

- 34 現在是 git 工作目錄，**不要再用 `deploy/push.sh`**（rsync 會讓 git 紀錄亂掉）。
- 密碼、憑證、部署紀錄（`deploy/.env`、`mosquitto/certs`、`deploy/.state`）只在 34 上，`sync` 不會動到。
- `sync` 升級儀表板前會先備份到 Mac 的 `frontend/artifacts/dashboard-backups/`。
- `sync` 結果裡 `unconfirmedQueries` 大於 0：代表有查詢看起來像舊版但不確定，腳本不會自動改，把輸出交給開發者確認。
- 換部署機時，改 `deploy/vm.sh` 與 `deploy/git-sync.sh` 最上面的預設值（instance、zone、位址）。
