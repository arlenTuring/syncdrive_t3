### 三、API 金鑰與 MQTT 用戶端憑證

呼叫 REST API 與連線 MQTT 所需的憑據，透過同一支端點取得，**不是固定值**：

```
POST http://34.80.84.224:3100/syncdrive-api/auth/token
Content-Type: application/json

{ "username": "<上方入口帳號>", "password": "<上方入口密碼>" }
```

回應包含：

| 用途 | 欄位 |
|------|------|
| REST 呼叫用的 `x-api-key` | `api_key` |
| 金鑰有效期（預設 24 小時，可用 `ttl_minutes` 指定） | `expires_at`、`expires_in_minutes` |
| MQTT 連線用的根 CA 憑證 | `mqtt.ca_certificate` |
| 用戶端憑證鏈所需的中介 CA | `mqtt.intermediate_certificate` |
| 各車 MQTT 用戶端憑證與私鑰 | `mqtt.clients[]` |

完整欄位定義與範例見[介接說明書](協力廠商介接說明書.md) §一。金鑰逾期後所有對外介面回應 `401`，重新呼叫本端點即可取得新的一把。MQTT 用戶端憑證於申請當下簽發，有效期等於該次的 `ttl_minutes`，與 API 金鑰同時失效——一次呼叫即同時取得新的金鑰與新的憑證。TLS 連線時 `ca_certificate` 與 `intermediate_certificate` 兩者皆需納入信任鏈。

| 用途 | 端點 |

### 五、MQTT

| | |
|---|---|
| 位址 | `mqtts://34.80.84.224:8883` |
| 傳輸層 | TLS，雙向驗證（用戶端憑證） |
| 身分 | 憑證 CN，等於車輛代號（例 `PMS-05`） |

詳見介接入口的[車端介接說明書](車端介接說明書.md) §二。

### 六、常見問題

| 狀況 | 原因 |
|------|------|
| `POST /auth/token` 回 `401` | 帳號或密碼不正確 |
| 其他 API 回 `401` | 沒帶 `x-api-key`，值不正確，或金鑰已逾 `expires_at` |
| 班表 API 回 `404` | 目前庫內沒有已發布班表。這是正常回應，不是故障 |
| 即時 ETA 各站都是空的 | 該時段車輛都在整備區，沒有正線車。換時段再看 |
| `data_quality` 是 `DEGRADED` | 部分車輛資料逾時，其餘資料仍可用 |
| MQTT 連不上 | 憑證錯誤、逾期，或未帶憑證 |

**失聯是以「資料變舊」呈現，不是資料消失。**車輛停止回報時仍會出現在回應中，
只是 `data_age_seconds` 持續累加、`arrival_state` 轉為 `UNKNOWN`。請檢查這兩個
欄位，不要只判斷車輛是否存在。

有任何回應與文件不符之處，請以實際回應為準並通知我方。
