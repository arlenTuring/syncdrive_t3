# 排程訂單管理

## 查看日曆

進入「服務管理模組 → 排程訂單管理」後，預設顯示網站時區的今天。可用載具選單篩選，使用前後箭頭移動一天或一週，並以右上選單切換日／週檢視。每一天固定顯示執行中、待執行、異常、結束、取消五個互斥分類；分類數字來自同一份後端投影。

日曆包含已建立的營運訂單、合法保存的人工排程，以及已採用每日班表中尚未發行的任務。相同計畫發行成訂單後只顯示一次。「尚未下發」表示目前只有計畫，車端還不能用 `queryById` 取得該單，也不代表車端已接受。

每個日期與狀態先顯示前 20 筆，可用「載入更多」逐批增加，狀態總筆數仍顯示完整結果。缺少 `planned_start` 的舊訂單不會以建立時間猜測日期；頁面會另列未排程筆數。

## 建立人工排程

1. 按「建立排程」，輸入顯示名稱與未來的計畫開始時間。
2. 選擇一台已啟用且可提供服務的註冊載具。
3. 按「選擇路線任務」，從資料庫既有路線中單選一條；展開群組不等於選取。
4. 核對唯讀站序與動作摘要後按「建立」。

取消或關閉不會保存資料。建立成功只代表未發布計畫已寫入資料庫；到達既有調度發行窗口、即時調度開關啟用且營運時鐘為 realtime 後，才會沿既有 `OrderService` 鏈建立實體訂單。頁面不提供首站手動／自動發車、任意媒體、修改共用路線、刪站或改寫車端狀態。

沒有啟用地圖、路線站序不足兩站、載具失效、開始時間已過或同一載具同時段衝突時，後端會拒絕建立並顯示原因。重送相同 request key 與內容會回原排程；相同 key 不同內容會回衝突。

## 查看詳情

點選卡片開啟右側詳情。尚未發行時顯示排程編號與「尚未下發」；發行後顯示真實 `order_id`、原始狀態、計畫起訖、可證實的實際起訖、原因與建立時站序。計畫時間不會冒充實際時間，缺少可靠資料顯示「—」或「未提供」。

需要權限：查看為 `service.scheduled-orders.view`；建立為 `service.scheduled-orders.create` 或既有 `operations.dispatch.create`。所有內部 API 均使用登入 Session，異動另需 CSRF 驗證。

## 查詢真實訂單記錄

「服務管理模組 → 訂單管理記錄」只查已存在的 `operation_orders`，不混入尚未發行的班表或人工排程。可依關鍵字、時間、載具及待執行／執行中／異常／結束／取消篩選，分頁與排序由後端執行；詳情沿用同一訂單投影與建立時站序。

首次進入、修改條件或由其他頁帶入條件時都不會自動查詢；按「搜尋」才套用條件，之後翻頁與排序維持該次條件快照。按「重置」會取消進行中的請求並回到未查詢狀態。需要獨立權限 `service.order-records.view`。
