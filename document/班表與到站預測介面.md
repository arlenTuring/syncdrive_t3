| 項目 | 內容 |
|------|------|
| 提供方 | 台智駕 SyncDrive T3 車輛行車管理系統 |
| 版本 | v2.0（2026-08-28） |
| 適用範圍 | 班次計畫時刻、站點與車輛到站預測之唯讀介面 |

## 一、服務範圍

| 類別 | 內容 | 提供的 API |
|------|------|-----------|
| 計畫值 | 已發布班表之逐站時刻、站點事件流 | `GET /syncdrive-api/operation-shift/timetable/trips`<br>`GET /syncdrive-api/operation-shift/timetable/station-etas` |
| 即時值 | 車輛已進入到站門檻之提示、預計抵達各停靠點的時刻與剩餘秒數 | `GET /syncdrive-api/vehicles/eta/by-station`<br>`GET /syncdrive-api/vehicles/eta/by-vehicle` |

即時值兩支 API 提供**同一份資料的兩種索引方式**：`by-station` 以停靠點為主鍵，供站端顯示；`by-vehicle` 以車輛為主鍵，供車輛追蹤畫面。計畫值兩支 API 同理：`trips` 以班次為主鍵，`station-etas` 以站點事件為主鍵。

**所有回應欄位的意義、型別與值域，統一定義於[第五章 資料模型](#五資料模型)。** 各 API 章節僅列出請求方式與回應範例。

## 二、共用約定

### 2.1 通訊規範

| 項目 | 規範 |
|------|------|
| 協定 | HTTP/1.1 以上 |
| 方法 | `GET` |
| 回應格式 | `application/json; charset=utf-8` |
| 認證 | `x-api-key` 請求標頭 |
| 壓縮 | 支援 `Accept-Encoding: gzip`（即時值 API），應啟用 |
| 條件式請求 | 即時值 API 支援 `ETag` / `If-None-Match` |
| 請求逾時 | 使用方應設定 5 秒 |
| 時鐘同步 | 雙方必須以 NTP 同步 |

### 2.2 識別碼格式

| 欄位 | 格式 | 範例 |
|------|------|------|
| `vehicle_code` | `PMS` + 兩碼數字 | `PMS05` |
| `station_id` | 停靠點識別碼 | `station_4` |
| `trip_code` | 路線代號 + `HHMM` | `ST0007` |
| `order_id` | `[YYMMDD]-[trip_code]` | `260816-ST0007` |

### 2.3 時間表示

全系統統一採用 **13 位 Unix Epoch 毫秒（Long）**，不使用 ISO 8601 字串。即時值 API 每一個時間點另附可讀式字串，供顯示端直接使用：

| 欄位型式 | 型別 | 用途 | 範例 |
|---------|------|------|------|
| `*_at` | Long | **權威值**。13 位 Unix Epoch 毫秒。所有運算、比較、排序一律以此為準 | `1786842023000` |
| `*_clock` | String | **顯示值**。當地時刻 `HH:MM:SS`，24 小時制 | `"09:00:23"` |

`*_clock` 由中心端依當地時區換算後提供，兩者恆指向同一時刻；若不一致，以 `*_at` 為準。跨午夜直接以次日時刻表示，不使用 `25:10:30` 這類超過 `24:00:00` 的寫法，日期由 `*_at` 判定。

秒數型欄位（`eta_seconds`、`delay_seconds`、`data_age_seconds` 等）為**時間長度**，非時間點，不適用上述規則。

### 2.4 列舉值

所有列舉值使用 `SCREAMING_SNAKE_CASE`。使用方應忽略未知列舉值並套用預設處理：`arrival_state` 未知時視為 `UNKNOWN`。

### 2.5 停靠點清單

回應中一律列出全部已啟用停靠點，包含當下無車駛近者，以利站端固定顯示版面。現行停靠點清單與座標見[車端介接說明書](車端介接說明書.md) §四。

## 三、計畫值 API

計畫值讀取已發布班表；若無已發布班表，改讀最新含排班結果之草稿（回應 `meta.source` 標示為 `draft_fallback`）；兩者皆無時回應 `404`。

### 3.1 `GET /syncdrive-api/operation-shift/timetable/trips`

回傳全部班次與逐站計畫時刻。

**查詢參數**

| 參數 | 型別 | 必填 | 預設 | 說明 |
|------|------|:---:|------|------|
| `from` | String | | `00:00:00` | 時間下限，`HH:MM:SS` |
| `to` | String | | `24:00:00` | 時間上限 |

過濾規則：班次時段與 `[from, to]` 有重疊即納入（非要求整段落在區間內）。回傳範圍為 plan 內全部任務類型（載客正線、保養、行檢、充電、待命、調度等），僅略過純轉場區段；非載客任務通常無站序，`stations` 為 `[]`。

**請求範例**

```bash
curl -s "http://34.80.84.224:3100/syncdrive-api/operation-shift/timetable/trips" \
  -H "x-api-key: <API_KEY>"
```

**回應範例**

```json
{
  "meta": {
    "shift_id": "OS-DRAFT-XXXXXXXX",
    "name": "尖峰示範班表",
    "publish_status": "published",
    "source": "published",
    "generated_at": "2026-08-04T03:00:00.000Z",
    "updated_at": "1722744000000"
  },
  "filter": { "from": "00:00:00", "to": "24:00:00", "from_second": 0, "to_second": 86400 },
  "trip_count": 2,
  "trips": [
    {
      "trip_code": "ST0007",
      "task_type": "passenger",
      "route_code": "ST",
      "route_name": "S2W上行 > T3上行",
      "card_start": "00:07:40",
      "card_end": "00:11:30",
      "card_start_second": 460,
      "card_end_second": 690,
      "stations": [
        {
          "order": 1, "station_id": "station_6", "station_name": "S2W上行",
          "role": "origin", "arrival": null, "departure": "00:07:40",
          "dwell_seconds": 0, "travel_to_next_seconds": 100
        },
        {
          "order": 2, "station_id": "station_4", "station_name": "T3上行",
          "role": "terminal", "arrival": "00:10:40", "departure": null,
          "dwell_complete": "00:11:30", "dwell_seconds": 50, "travel_to_next_seconds": null
        }
      ]
    }
  ]
}
```

**站點欄位語意**

| `role` | 怎麼讀 |
|--------|--------|
| `origin` | 只看 `departure`（＝本卡開始）。`arrival` 固定為 `null`（抵達屬上一卡末站） |
| `intermediate` | `arrival` + `departure` |
| `terminal` | `arrival` + `dwell_complete`（＝卡結束，完成靠站／緩衝） |

`stations[0].departure` 恆等於 `card_start`；末站 `dwell_complete` 恆等於 `card_end`。

### 3.2 `GET /syncdrive-api/operation-shift/timetable/station-etas`

將全部正線班次拆成「站點事件」時間線，供站端固定訂閱某一站。

**查詢參數**

| 參數 | 型別 | 必填 | 說明 |
|------|------|:---:|------|
| `from` / `to` | String | | 事件時刻（抵達或離站）落在區間內才回傳 |
| `station_id` | String | | 只取單一停靠點 |

每筆事件含到站時刻 `eta_arrive`、離站／靠站完成時刻 `eta_depart`、緩衝秒數 `buffer_seconds`、`role`。回應之 `stations[]` 一律列出全部已啟用停靠點（含事件為空者），供站端固定頁籤顯示。

**請求範例**

```bash
curl -s "http://34.80.84.224:3100/syncdrive-api/operation-shift/timetable/station-etas?station_id=station_4" \
  -H "x-api-key: <API_KEY>"
```

**回應範例**

```json
{
  "meta": {
    "shift_id": "OS-DRAFT-XXXXXXXX",
    "publish_status": "published",
    "source": "published",
    "generated_at": "2026-08-04T03:00:00.000Z"
  },
  "filter": { "from": "00:10:00", "to": "00:12:00", "station_id": "station_4" },
  "eta_count": 1,
  "etas": [
    {
      "station_id": "station_4",
      "station_name": "T3上行",
      "role": "terminal",
      "eta_arrive": "00:10:40",
      "eta_depart": "00:11:30",
      "eta_arrive_second": 640,
      "eta_depart_second": 690,
      "dwell_seconds": 50,
      "buffer_seconds": 14,
      "trip_code": "ST0007",
      "route_code": "ST",
      "route_name": "S2W上行 > T3上行"
    }
  ]
}
```

## 四、即時值 API

### 4.1 `GET /syncdrive-api/vehicles/eta/by-station`

回傳各停靠點接下來將抵達的車輛預測。

**查詢參數**

| 參數 | 型別 | 必填 | 預設 | 說明 |
|------|------|:---:|------|------|
| `station_id` | String | | 全部 | 指定停靠點，可重複指定多個 |
| `limit_per_station` | Int | | `3` | 每站回傳筆數，值域 1–10 |

**請求範例**

```bash
curl -s "http://34.80.84.224:3100/syncdrive-api/vehicles/eta/by-station?station_id=station_4&limit_per_station=3" \
  -H "x-api-key: <API_KEY>"
```

**回應範例：一般情形**

```json
{

    "generated_at": 1786842000000,
    "generated_clock": "09:00:00",
    "shift_id": "OS-DRAFT-MSEEXIN9",

    "data_quality": "OK"
  },
  "station_count": 1,
  "stations": [
    {
      "station_id": "station_4",
      "station_name": "T3上行",
      "etas": [
        {
          "vehicle_code": "PMS05",
          "order_id": "260816-ST0007",
          "trip_code": "ST0007",
          "route_code": "ST",
          "route_name": "S2W上行 > T3上行",
          "vehicle_phase": "TRANSITING",
          "arrival_state": "APPROACHING",
          "eta_seconds": 25,
          "eta_at": 1786842023000,
          "eta_clock": "09:00:23",
          "distance_to_station_m": 120.0,
          "plan": {
            "planned_arrival_at": 1786842010000,
            "planned_arrival_clock": "09:00:10",
            "planned_departure_at": null,
            "planned_departure_clock": null,
            "delay_seconds": 13,
            "delay_state": "ON_TIME"
          },
          "observed_at": 1786841998000,
          "observed_clock": "08:59:58",
          "data_age_seconds": 2
        }
      ]
    }
  ]

```

**回應範例：停靠中、資料逾時、無車駛近**

```json
{
  "meta": { "generated_at": 1786842000000, "generated_clock": "09:00:00", "source": "published", "data_quality": "DEGRADED" },
  "station_count": 2,
  "stations": [
    {
      "station_id": "station_2",
      "station_name": "N2W下行",
      "etas": [
        {
          "vehicle_code": "PMS03", "order_id": "260816-NT0900", "trip_code": "NT0900",
          "arrival_state": "AT_STATION", "eta_seconds": 0, "distance_to_station_m": 0.0,
          "plan": { "planned_arrival_at": 1786841970000, "planned_departure_at": 1786842020000, "delay_seconds": 29, "delay_state": "ON_TIME" },
          "observed_at": 1786841999000, "data_age_seconds": 1
        }
      ]
    },
    { "station_id": "station_1", "station_name": "N2W上行", "etas": [] }
  ]
}
```

- 停靠中：`arrival_state` 為 `AT_STATION`，`plan.planned_departure_*` 提供預計發車時刻。
- 資料逾時：`data_age_seconds` 超過門檻，`arrival_state` 為 `UNKNOWN`，所有即時推估欄位為 `null`。使用方必須顯示資料中斷，不得沿用先前取得的 ETA。
- 無車駛近：`etas` 為空陣列。
- 因存在逾時車輛，`meta.data_quality` 轉為 `DEGRADED`。

### 4.2 `GET /syncdrive-api/vehicles/eta/by-vehicle`

回傳各車輛接下來將抵達的停靠點預測。

**查詢參數**

| 參數 | 型別 | 必填 | 預設 | 說明 |
|------|------|:---:|------|------|
| `vehicle_code` | String | | 全部 | 指定車輛，可重複指定多個 |
| `next_stops` | Int | | `3` | 每車往後推算站數，值域 1–10 |

**請求範例**

```bash
curl -s "http://34.80.84.224:3100/syncdrive-api/vehicles/eta/by-vehicle?vehicle_code=PMS05&next_stops=3" \
  -H "x-api-key: <API_KEY>"
```

**回應範例**

```json
{
  "meta": { "generated_at": 1786842000000, "generated_clock": "09:00:00", "source": "published", "data_quality": "OK" },
  "vehicle_count": 1,
  "vehicles": [
    {
      "vehicle_code": "PMS05",
      "vehicle_phase": "TRANSITING",
      "order_id": "260816-ST0007",
      "trip_code": "ST0007",
      "route_code": "ST",
      "route_name": "S2W上行 > T3上行",
      "position": { "latitude": 25.077612, "longitude": 121.232545, "heading": 1.49, "velocity_kph": 10.5 },
      "next_stops": [
        {
          "sequence": 1, "station_id": "station_4", "station_name": "T3上行",
          "arrival_state": "APPROACHING", "eta_seconds": 25, "eta_at": 1786842023000,
          "eta_clock": "09:00:23", "distance_to_station_m": 120.0,
          "plan": { "planned_arrival_at": 1786842010000, "planned_arrival_clock": "09:00:10", "delay_seconds": 13, "delay_state": "ON_TIME" }
        }
      ],
      "observed_at": 1786841998000,
      "observed_clock": "08:59:58",
      "data_age_seconds": 2
    }

}
```

`distance_to_station_m` 僅於 `sequence` 為 `1`（車輛當前行駛中的目標站）時有值，後續站點為 `null`。車端資料逾時時，`position` 為 `null`，且僅回傳 `sequence` 為 `1` 的站點（無法外推後續站點）。

`position.velocity_kph` 單位為 **km/h**（欄位名已含單位）。車端 MQTT 介面傳輸的
`kinematics.velocity` 單位是 **m/s**，本 API 對外輸出前已乘 3.6 換算，使用方不需
再換算。

## 五、資料模型

### 5.1 `meta`（回應層級資訊，即時值 API）

| 欄位 | 型別 | 說明 |
|------|------|------|
| `generated_at` | Long | 中心端產生本次快照的時刻 |
| `generated_clock` | String | `generated_at` 的當地時刻表示 |
| `shift_id` | String \| null | 本次計畫值所依據的班表識別碼 |
| `source` | String | 計畫值來源：`published`（已發布）／`draft_fallback`（草稿，僅供參考）／`none`（無可用班表） |
| `data_quality` | String | 見 5.2 |

### 5.2 `data_quality`（資料品質）

依全車隊回報狀況彙總。

| 值 | 意義 | 使用方處理 |
|----|------|-----------|
| `OK` | 全部車輛回報正常 | 正常顯示 |
| `DEGRADED` | 部分車輛資料逾時，或班表未載入 | 顯示，並對 `arrival_state` 為 `UNKNOWN` 者標示資料中斷 |
| `DOWN` | 無法取得任何車輛資料 | 必須停止顯示 ETA，改顯示資料中斷 |

### 5.3 `vehicle_phase`（車輛營運階段）

車端於[營運任務狀態協議](營運任務狀態協議.md)回報之營運階段，本介面原值透傳，不改寫、不擴充。車端未提供或資料逾時時為 `null`。

### 5.4 `arrival_state`（到站狀態，衍生欄位）

本欄為即時值介面依車端回報值計算之衍生欄位，非 MQTT 協議定義之狀態。

| 值 | 意義 | 判定條件 |
|----|------|---------|
| `EN_ROUTE` | 行駛中，尚未接近 | `eta_seconds` 與 `distance_to_station_m` 均未達門檻 |
| `APPROACHING` | 即將進站 | `eta_seconds ≤ 60` 或 `distance_to_station_m ≤ 200` |
| `DOCKING` | 進站對位中 | 車端 `PLATFORM_DOCKING` 任務為 `IN_PROGRESS` |
| `AT_STATION` | 停靠中 | 車端 `OPEN_DOORS` 任務已完成，且尚未觸發 `CLOSE_DOORS` |
| `DEPARTED` | 已離站 | 車端 `STATION_DEPARTURE` 任務已完成 |
| `UNKNOWN` | 無法判定 | 車端資料逾時，或缺少目標站資訊 |

### 5.5 到站時刻欄位

| 欄位 | 型別 | 說明 |
|------|------|------|
| `eta_seconds` | Int \| null | 距抵達該停靠點還有幾秒。以 `observed_at` 為基準，非以使用方收到回應的時刻為基準 |
| `eta_at` | Long \| null | 預計抵達之絕對時刻。恆等於 `observed_at + eta_seconds × 1000` |
| `eta_clock` | String \| null | `eta_at` 的當地時刻表示 |
| `distance_to_station_m` | Double \| null | 車輛距該停靠點的路徑距離，公尺 |

使用方**必須**以 `eta_at`（絕對時刻）計算剩餘時間，不得以 `eta_seconds` 自輪詢時刻起算倒數：

```
剩餘秒數 = (eta_at - 使用方當前時間) / 1000
```

`eta_seconds` 是以 `observed_at` 為基準的值；使用方收到回應時，該值已經過 `data_age_seconds` 秒加上網路傳輸時間，以其自輪詢時刻起算倒數會累積誤差。

### 5.6 `plan`（班表計畫值）

| 欄位 | 型別 | 說明 |
|------|------|------|
| `planned_arrival_at` | Long \| null | 計畫抵達時刻 |
| `planned_departure_at` | Long \| null | 計畫發車時刻。僅於該站為起站，或 `arrival_state` 為 `AT_STATION` 時有值 |
| `delay_seconds` | Int \| null | `eta_at` 減 `planned_arrival_at`，單位秒。正值表示晚於計畫 |
| `delay_state` | String | 誤點狀態，見 5.7。**暫定定義**，現階段應以 `delay_seconds` 為準 |

### 5.7 `delay_state`（誤點狀態）— 暫定

> 門檻值與狀態分級尚未經營運確認，將於試營運後調整。現階段使用方應以 `delay_seconds`（數值）為準，自行決定顯示門檻。

| 值 | 暫定條件 | 意義 |
|----|---------|------|
| `EARLY` | `delay_seconds < -30` | 早到 |
| `ON_TIME` | `-30 ≤ delay_seconds ≤ 60` | 準點 |
| `MINOR_DELAY` | `60 < delay_seconds ≤ 180` | 輕微誤點 |
| `MAJOR_DELAY` | `delay_seconds > 180` | 顯著誤點 |
| `NO_PLAN` | 無對應計畫班次 | 不判定誤點 |

### 5.8 資料新鮮度欄位

| 欄位 | 型別 | 說明 |
|------|------|------|
| `observed_at` | Long | 本筆推估所依據的車端回報時刻 |
| `data_age_seconds` | Int | `generated_at` 減 `observed_at`，單位秒 |

車端以 1 Hz 上行，中心端逐筆覆寫該車的最新狀態，**不設過期清除**。車輛停止回報時，中心端仍保有其最後一筆資料，`data_age_seconds` 將持續累加——**失聯是以「資料變舊」呈現，不是以「資料消失」呈現**，使用方必須檢查 `data_age_seconds` 或 `arrival_state`，不可僅以欄位是否存在判斷。`data_age_seconds` 超過門檻（預設 90 秒）時，`arrival_state` 轉為 `UNKNOWN`。

## 六、輪詢規範

### 6.1 建議輪詢間隔（即時值 API）

| 項目 | 值 |
|------|----|
| 建議間隔 | **60 秒** |
| 可接受範圍 | 30–60 秒 |
| 最小間隔 | 10 秒（低於此值回應 `429`） |
| 最大間隔 | 60 秒（`APPROACHING` 門檻為 60 秒，間隔大於此值時可能觀測不到即將進站狀態） |

低於 15 秒的輪詢不提升顯示精度：ETA 的實質變化來自車輛移動，顯示精度為分鐘級。計畫值 API（班表變動頻率低）無固定輪詢建議，使用方可依班表發布事件觸發重新讀取。

### 6.2 重試與逾時

| 情形 | 處理 |
|------|------|
| 請求逾時（5 秒） | 沿用前一份資料並標示過期，等待下一排程週期 |
| `5xx` 回應 | 同上，不應立即重試 |
| `429` 回應 | 依 `Retry-After` 標頭延後 |
| `304` 回應（即時值 API） | 沿用前一份資料，視為成功 |

每次回應均為完整快照，漏取一輪不會造成資料累積落後，下一輪即補齊。

### 6.3 ETag 使用（即時值 API）

```http
GET /syncdrive-api/vehicles/eta/by-station HTTP/1.1
x-api-key: <API_KEY>
If-None-Match: "a1b2c3d4"
```

資料未變更時回應 `304 Not Modified`。

## 七、錯誤處理

| 狀態碼 | 情形 |
|-------|------|
| `200` | 成功，包含空結果 |
| `304` | 資料未變更（即時值 API） |
| `400` | 參數格式或值域不符 |
| `401` | `x-api-key` 缺少、不正確或已過期 |
| `404` | 指定的 `vehicle_code`／`station_id` 不存在，或計畫值 API 無可用班表 |
| `429` | 超過輪詢頻率限制（即時值 API） |
| `503` | 服務降級，無法提供即時資料 |

錯誤回應格式：

```json
{ "error": "INVALID_PARAM", "detail": "limit_per_station 必須為 1 至 10 的整數" }
```

## 九、計畫值與即時值的關係

兩者資料來源不同，不互相取代。

| 視角 | 計畫值 | 即時值 |
|------|-------|-------|
| 依站 | `GET /operation-shift/timetable/station-etas` | `GET /vehicles/eta/by-station` |
| 依班次／車 | `GET /operation-shift/timetable/trips` | `GET /vehicles/eta/by-vehicle` |

| | 計畫值 | 即時值 |
|---|-------|-------|
| 資料來源 | 已發布班表 | 車端回報 |
| 車輛識別 | 無 | 有（`vehicle_code`） |
| 可用條件 | 班表已發布 | 車輛正在回報 |
| 用途 | 時刻表公告、營運規劃 | 現場顯示、監控 |

即時值 API 於 `plan` 子物件內嵌對應的計畫值，供直接比對，無需另行呼叫計畫值 API。
