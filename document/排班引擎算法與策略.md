> 對應程式：`frontend/src/features/shift-list/utils/schedule-engine/`

更新日期：2026-08-01

## 1. 策略閘門（S1–S4）

| 代號 | 名稱 | 現行實作 |
|------|------|----------|
| S1 | 恢復時間 | 同車兩趟之間至少保留 `minimumRecoveryTimeSeconds`（預設 30s） |
| S2 | 換線緩衝 | **與恢復相加**，不可取 max：換線時空檔 = 恢復 + 前一路線 `switchBufferAfterSeconds` |
| S3 | 時鐘對齊 | 發車與占用長度向上對齊 **10 秒格** |
| S4 | 靠站緩衝 | 各站停靠 + **固定秒數** `dwellSlackSeconds`（不是停靠時間的百分比） |

正線連續優先：在硬約束內維持服務；整備開頭可被讓渡餘裕壓縮、保養尾巴可插進場載客；不可用違規班次假裝達成班距／PPHPD。

空檔統一公式（`physics.resolveInterTripGapSeconds`）：

```
同路線：下一發車 ≥ 前趟結束 + 恢復
導通中段換線：下一發車 ≥ 前趟結束 + 換線緩衝
折返／非繼任換線：下一發車 ≥ 前趟結束 + 恢復 + 前一路線換線緩衝
```

## 2. 生產主路徑（`template`）

建立班表 adapter（`runShiftScheduleEngineForDraft`）固定：

```ts
passengerTimetableMode: 'template'
```

語意：以時間模板上的正線視窗與屬性為服務承諾，每個班距脈衝派出一個**完整合法交路**；同服務方向的連續 route legs 是同一班續行。

```
normalizeInput
  ├─ buildRouteSuccessorPolicy（有圖但驗證無效則停止，不得退回執行順序）
  ├─ 產生完整交路起班脈衝（S3 對齊；跨時段銜接取 max(舊班距, 新班距)）
  ├─ 從所有可用車選車，沿 successor chain 原子展開整輪
  ├─ 掛不上則記錄 UNSERVED_SERVICE_PULSE
  └─ 合併非正線任務
assignRoutes（輪替環硬指派 + 占用含 S4）
expand（區塊；正線可壓縮整備開頭，結束時間不變）
validate
→ plan + report
```

算法識別碼：

| ID | 職責 |
|----|------|
| `periodic-cycle-headway-v2` | 完整交路起班脈衝與原子整輪 |
| `execution-order-ring-v1` | 完全沒有關聯圖的舊資料相容 |
| `relation-graph-through-anchors-v1` | 導通驗證有效時：參考路徑為輪替環 |
| `rotation-cycle-completion-v1` | 執行順序環的週期補完／撤回 |
| `rotation-cycle-through-anchors-v1` | 舊補完工具；v2 自動生成主路徑不再呼叫 |
| `constraint-greedy-v1` | 執行順序硬輪替指派 |
| `route-assignment-relation-graph-v1` | 導通環硬輪替指派 |

切換閘門（`buildRouteSuccessorPolicy`）：Step 4 `throughAnchors` 指紋仍有效、關聯圖有連線、且能算出全優先導通 → 走圖模式；有圖但條件不成立時停止生成。只有完全沒有圖的舊資料可用執行順序環。

## 3. 掛車要點

1. **脈衝是完整交路起班**：NT→TS 等同向連續 legs 只算一班；後續上行由同車自然接續。
2. **準點掛不上**：
   - 該方向已有前班 → 可延後，但不可跨越下一脈衝（吸收遲到）。
   - 該方向尚無前班 → 最多延後 120 秒。
   - 車因上一趟「均」占用太晚 → **把上一趟壓到快** 再試掛，優先於丟掉脈衝。
3. **掛車班距下限**：上一班同方向實際發車 + max(前時段班距, 本時段班距, 車隊物理下限)。**整輪每一腿**（含後段腿）相對已掛同向班次（過去與未來）都須達目標班距，不可只守物理地板（否則會出現 ~20s 級擠班）。
3a. **行前／充電／機動調撥開輪例外**：開輪第一腿改用車站清除時間（衝突站靠站／離站＋遲到佔站＋緩衝％），不得用營運班距當插班門檻。
4. **整備開頭讓渡**：回程最晚可在「整備開始 + entrySlack」完成；不得以 entrySlack 提前結束前一整備預出車。空時段**不可**提前占用尾端。
5. **無車可掛** → 留下 `UNSERVED_SERVICE_PULSE`，不可靜默遺失。
6. **開輪相位**：行前／充電／機動出場站對齊起點路線（僅該列之後仍有正線時）；純機動不對齊、不派正線。圖模式優先選折返錨點出發路線。
7. **車數／列數**：理論下限 ≈ ceil(完整交路週期 ÷ 班距)；時段短於「週期＋班距」、或整備占窗多時，實際需要更多列。時間模板「正線建議」列與此一致。

---

## 4. 原子化整輪

掛車時即依 policy 展開整個 route chain；中段依 S2 接續，折返才套 S1。整輪須在「整備開始 + entrySlack」前完成；塞不下就不掛該脈衝，不先輸出半輪再補回程。

---

## 5. 路線指派

同一時間線嚴格依 Step 4 已驗證 successor chain 輪替，並驗證前趟 terminal＝後趟 origin。不可用 executionOrder 取代有效關聯圖。

占用秒數：

```
有效平均行駛 = stationLegTravels 完整？ Σ(leg.avg) : avgTravelTimeSeconds
占用（預設） = snap↓10s( 有效平均行駛 + Σ(站停 + 靠站緩衝) )（均）
趕班距時可壓到最快占用（快）
```

---

## 6. `headway` 模式（次要／測試）

`passengerTimetableMode: 'headway'` 會依班距生成時刻並走較舊的掛車輔助（含已標 `@deprecated` 的 EAT 輔助函式）。  
**建立班表 UI 不使用此模式**；單元測試可覆蓋。實作細節以 `normalizeInput.ts` / `generateDepartures.ts` 為準，勿再當成產品預設。

---

## 7. 評分與運能

引擎不以「模板目標班距」假裝達標。PPHPD／容量趨勢由**實際同方向發車間隔**換算（見調整／預覽的 capacity 圖）。可行性以 `report.ok` 與 issue codes 為準。

---

## 8. 限制

| 項目 | 影響 |
|------|------|
| 無全局回溯 | 極端案例可能次優；缺口如實呈現 |
| 跨時段不強制整點相位 | 靠班距交錯與開頭讓渡維持連續 |
| 人工固定班次 | 無法自動撤回時才報 `ROTATION_CYCLE_INCOMPLETE` |
