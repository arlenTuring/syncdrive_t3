## 程式變更

**主系統（syncdrive_t3，未提交）**

- `backend/src/dispatch/dispatch.controller.ts`：POST operating-clock 接受 `expected_run_id`，與目前時鐘不符回 409（不覆蓋別的執行端）；GET operating-clock 允許執行端 API 金鑰讀取（同一把金鑰本來就能寫，執行端要讀回來對帳）。
- `backend/src/dispatch/dispatch.operating-clock.spec.ts`（新）：相符切換、不符 409、即時冪等、心跳不受影響，4 項。
- `backend/scripts/maintenance/replay-batch-cleanup.js`（新）：dry-run／apply／restore 一次性維護工具（見下）。
- `frontend/src/features/dashboard/constants/demoSql.ts`：正線、整備、車輛卡共用 `liveTaskScopeSql`（目前營運日、時窗涵蓋現在或車端仍回報；待發只看兩小時內）與 `liveTaskRankSql`（執行中 → 故障 → 待發）；整備改為一車一張。
- `frontend/scripts/verify-live-task-sql.ts`（新）：在交易內放舊營運日故障、今天執行中、跨午夜長整備、遠期待發，跑真正的三份 SQL 後 ROLLBACK，9 項全符合。
- `frontend/src/features/dashboard/utils/operatingClock.ts`、`elements/ClockWidget.tsx`：時鐘日期旁顯示「即時／重播 ×N／重播暫停／重播失聯／重播已結束／時鐘失聯」；測試 1 項。

**模擬器（syncdrive_t3_simulator，未提交）**

- `src/operatingClock.js`：`release()` 只動本機；新增可 await 的 `syncRealtime()`——先讀主機時鐘，別的執行端仍在推進（有心跳，暫停中也算）就拒絕；送 `{mode:'realtime', expected_run_id}`；回應遺失時讀一次對帳；確認 realtime 才成功。
- `server.js`：`/api/run/start` 在車隊上線、解除暫停接單之前加「營運時鐘」步驟；切回接受系統派單、恢復後端調度都走同一個流程；期間目標被換掉就作廢。
- `public/planReplay.js`：切回接受系統派單時，主系統時鐘沒切回會顯示原因。
- `test/operatingClockSync.test.js`（新）：重啟後主系統舊暫停重播、本來就即時、別人推進中拒絕、自己的重播可收回、讀寫之間被接手 409、回應遺失對帳、401／逾時、本機重播進行中，8 項。
