# 月台門與車門 MQTT 協議

> 目前版：2026-09-18。站點以 [T3 地圖清單](T3地圖站點與路線清單.md) 為準；訂單新規格見 [錯誤與對帳](訂單API錯誤與對帳.md)。

> 本文件為 **車門月台控制** 與場域 PSD 動畫專用的門體即時資料契約。  
> **不屬於** 四大核心協議（telemetry / operation / health / command-event）的閉鎖集合；若日後要納入文件交換主協議，需依 [Topic 命名規範 §五](MQTT%20通訊架構與%20Topic%20命名規範.md) 由雙方審閱。  
> 門控指令仍使用既有 [動態控制與特殊事件協議](動態控制與特殊事件協議.md) 的 `DOOR_CONTROL`；本協議只定義 **狀態上報**。

## 一、用途

中心端訂閱門體開度與顯示狀態，驅動車門月台控制列表／詳情指示器，以及地圖月台門線性開度。

---

> **連線認證**：車端一律連 **8883**，TLS 雙向驗證；客戶端憑證的 CN 必須
> 等於自身 `vehicle_code`。詳見
> [MQTT 通訊架構與 Topic 命名規範](MQTT%20通訊架構與%20Topic%20命名規範.md) §三。

## 二、 Topic

| 種類 | 方向 | Topic | Retain |
| :--- | :--- | :--- | :--- |
| 車門狀態 | 車端 ➔ 中心 | `v1/vtms/{vehicle_code}/door/update` | `true` |
| 月台門狀態 | 設施／模擬器 ➔ 中心 | `v1/vtms/{psd_id}/psd/update` | `true` |

- `{vehicle_code}`：`PMS01`～`PMS11`。
- `{psd_id}`：地圖 PSD 元件的 `facility.id`（單層，不可含 `/`）。
- 共通約束：JSON、根層 `timestamp` 為 13 位 Unix Epoch (ms)、狀態碼 `SCREAMING_SNAKE_CASE`。

中心端以 Socket.IO 事件 `mqtt/{完整 Topic}` 轉發。地圖圖台既有 `syncdrive/Gate/{id}` 可並存。

## 三、 六種顯示狀態（與設計稿對齊）

`display_state` 為列表指示器的唯一對照碼。發布端應填此欄；中心亦可由 `motion` + `open_percent` + `connection` + `alignment` / `alarm` 推導（優先序見下）。

| `display_state` | 設計稿 | 指示器 |
| :--- | :--- | :--- |
| `OPEN` | 供乘客上下車　常態（開） | 綠、左右分扇全開 |
| `CLOSING` | 動作中（關） | 橘；開度由大變小（分扇→實心） |
| `CLOSED` | 常態（關） | 藍實心 |
| `OPENING` | 動作中（開） | 橘；開度由小變大（實心→分扇） |
| `ALIGNMENT_ALARM` | 對位不一致　告警 | 紅實心 |
| `OFFLINE` | 失去連線 | 灰實心 |

**推導優先序（高→低）**

1. `connection = OFFLINE` → `OFFLINE`
2. `alarm = true` 或 `alignment = MISALIGNED` → `ALIGNMENT_ALARM`
3. `motion = OPENING` 或 `0 < open_percent < 100` 且正在增大 → `OPENING`
4. `motion = CLOSING` 或 `0 < open_percent < 100` 且正在減小 → `CLOSING`
5. `motion = OPEN` 或 `open_percent ≥ 99.5` → `OPEN`
6. 其餘 → `CLOSED`

`open_percent`：0＝全關、100＝全開；`OPENING`／`CLOSING` 時用以驅動分扇間距動畫。

## 四、 車門 `door/update`

```json
{
  "vehicle_code": "PMS01",
  "timestamp": 1713868200000,
  "connection": "ONLINE",
  "speed_mps": 0,
  "doors": [
    {
      "door_id": "RF",
      "label": "右前",
      "open_percent": 0,
      "motion": "CLOSED",
      "display_state": "CLOSED",
      "locked": true,
      "anti_pinch": "OK",
      "alarm": false
    }
  ]
}
```

`doors[]` 固定四扇，順序：右前 `RF`、右後 `RR`、左前 `LF`、左後 `LR`。

| 欄位 | 型別 | 說明 |
| :--- | :--- | :--- |
| `connection` | String | 車級連線：`ONLINE` / `OFFLINE`（OFFLINE 時四扇皆顯示灰） |
| `speed_mps` | Double | 行車速度（m/s）。與[車輛動態協議](車輛動態協議.md) `kinematics.velocity` 同單位。 |
| `door_id` | String | `RF` / `RR` / `LF` / `LR` |
| `open_percent` | Integer | 0～100 |
| `motion` | String | `CLOSED` / `OPENING` / `OPEN` / `CLOSING` |
| `display_state` | String | 上表六碼之一 |
| `locked` | Boolean | 自動鎖定 |
| `anti_pinch` | String | `OK` / `FAULT` |
| `alarm` | Boolean | 該扇告警（對位／防夾等） |

正線模擬器 motion 欄位對照：`door_fr_open_percent`→`RF`，`door_rr`→`RR`，`door_fl`→`LF`，`door_rl`→`LR`。

## 五、 月台門 `psd/update`

```json
{
  "psd_id": "psd-n2w-1",
  "timestamp": 1713868200000,
  "open_percent": 55,
  "motion": "OPENING",
  "display_state": "OPENING",
  "alignment": "ALIGNED",
  "connection": "ONLINE",
  "locked": false,
  "anti_pinch": "OK",
  "alarm": false
}
```

| 欄位 | 型別 | 說明 |
| :--- | :--- | :--- |
| `psd_id` | String | 與 Topic、地圖 `facility.id` 相同 |
| `open_percent` | Integer | 0～100 |
| `motion` | String | 同車門 |
| `display_state` | String | 六碼之一；`alignment = MISALIGNED` 應為 `ALIGNMENT_ALARM` |
| `alignment` | String | `ALIGNED` / `MISALIGNED` |
| `connection` | String | `ONLINE` / `OFFLINE` |

停靠連動（開關順序，ICL 與華電討論結論）：

| 階段 | 順序 |
| :--- | :--- |
| **開門** | 停穩後**先開月台門，再開車門** |
| **關門** | 離站**先關車門，再關月台門** |

月台門先開，車門才不會開向未防護的月台邊；關門反序，確保無人滯留於兩門之間。

本規則**只約束指令發送的先後，不等待前一步的回報**，兩者實際觀感近乎同時。
