# 車輛軌道判位修正：工作紀錄

目標是**判對軌道**，不是讓「定位未確認」消失。只在本機驗證，沒有部署 GCP。

## 接續方式

- 離線重播：`npx vitest run src/features/map-editor/vehicles/locateAnomalyReplay.spec.ts`，輸出 `LOCATE_REPLAY_SUMMARY`／`LOCATE_REPLAY_DETAIL` 兩行 JSON（逐台、逐筆的新舊比較）。
- 錄新的異常：在儀表板頁的 console 設 `window.__LOCATE_RECORDER__ = []`，圖台每次真的重算判位就記一筆（不是每個影格，上限 20000 筆）；`window.__LOCATE_RECORDER_MAP__` 是當時的地圖與路線。存檔方式見下方「錄製」。
- 全部測試：`npm test`（node:test 與 vitest 分流；單跑 vitest 會把 node:test 檔案報成 No test suite found，那不是失敗）。

## 階段二：判位與分支修正（完成）

- `utils/trackGenLocate.ts`
  - 結果結構：拿掉 `confidence`、`margin`；新增 `branchId`、`scoreMargin`（綜合評分差，診斷用）、`distanceMarginM`（幾何距離差，公尺）、`identity {status: confirmed|ambiguous, reason: geometry|continuity|route|heading|geometric_tie, rivals}`、`offRoute`。`headingConflict` 只是方向異常，不影響身分。
  - 分支識別：以設施 id 為分支（交叉／分岔已由 crossBranches 拆成 `母體~分支` 各自的設施，含各自真實中心線、圖面中心線與端點相接）；同一分支的多個 span 取最近的一個，不互相競爭。
  - 判定：先看幾何——與最近那條差在 `CANDIDATE_GATE_M`（1.2 m）內的才算分不開；**接縫上的前後段不算對手**（兩者端點相接、而且其中一方的投影停在相接那一端）。上一筆分支保留到比最近那條遠 0.3 m（`SEAM_HYSTERESIS_M`）才換。分不開時：任務路徑窗口與「上一筆＋其相連後續」只負責縮小合理分支；合理分支中最近的一條拉開 0.3 m（`GEOMETRY_SEPARATION_M`）就確認；還分不開才看可信車頭（先排除逆向，再比距離）；仍分不開、且不是停在原分支，才是 ambiguous。
  - 路線只在座標分不開的分支之間決定，不會把車吸回路線；所選分支不在路徑上回報 `offRoute`。
- `vehicles/routeCorridor.ts`：`shortestPiecePath`（有順序的最短路）、`buildRoutePath`（訂單有序站序 → 有序分支清單，含交叉進出口站，因此會走對應的交叉分支）、`routeWindow`（目前這一條＋往前 3 條；位置未知時整條）、`advanceRouteIndex`（只往前）。原本依目標站的走廊保留為備援。
- `vehicles/vehicleBranchTracker.ts`（新）：每台車保存上次確認的分支、沿線位置、位置、時間、訂單、路線、地圖。換圖、換任務、斷訊超過 15 秒、位置跳變（超過 max(30 m, 車速×時間×2＋10 m)）時不沿用；分不開的那一筆不更新狀態（不會被無限延續）；同一張任務路線重算時分支沿用、路徑進度不沿用。
- `vehicles/trackNetwork/locate.ts`、`resolveVehicleTrackPlacement.ts`：傳遞新欄位與 `routeBranchIds`。

## 未解決事項

- **方向矛盾是資料問題還沒查清**：PMS01 在 006／007、PMS05 在 016／017 行駛時，車頭跟圖資記的行車方向相反。現在判位正確（座標唯一候選），畫面標「方向異常」；但到底是圖資把這幾條的行車方向記反、還是路線本來就逆向使用這幾條，需要看圖資與路線設計再決定。
- **分支有效寬度**：圖資沒有每條分支的有效寬度（`trackGenLatPerBox` 是繪圖比例，不是寬度），所以沒有判定「離軌」。要有離軌判定需要先補寬度資料。
- **「資料過期」沒有做真的斷訊實測**：要讓某台車真的停止送遙測，得停掉模擬器或車隊，會影響正在跑的模擬，所以沒做。已確認的是反方向——資料持續進來時（包括停站的車）不會誤標過期；斷訊時的行為依賴 `vehicleLastSeen` 不再更新、overlay 每 2 秒重看時間，邏輯簡單但未實測。
- **任務路徑依賴後端訂單詳情**：車端 operation/update 只帶目標站；有序站序由前端依 order_id 向後端查一次。查不到的訂單（非調度引擎下的單、或查詢失敗）退回走廊。
