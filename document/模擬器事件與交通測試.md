# 模擬器事件與交通測試

本文說明怎麼用本機模擬器（`syncdrive_t3_simulator`）測主系統的事件管理、車輛圖台與訂單結案。模擬器是外部車端：只用車端既有的 MQTT 與對外 API，**不新增任何車端協議欄位**，也不直接寫主系統資料庫。下面提到的模擬器設定、事件紀錄與隨機排程都只存在模擬器本機。

相關協議：

- [車端介接說明書](對外介接/車端介接說明書.md) §4.6 `event/report`、§5 訂單進度
- [動態控制與特殊事件協議](對外介接/動態控制與特殊事件協議.md) 事件矩陣、§五 實作規範
- [營運任務狀態協議](對外介接/營運任務狀態協議.md) `vehicle_phase`
- [訂單API錯誤與對帳](對外介接/訂單API錯誤與對帳.md) `order/active` 對帳

## 一 日常流程

1. 模擬器 <http://127.0.0.1:4300> 分頁上方的共用頂部列選對測主機（第一次預設 GCP，之後記住上次成功的），按「連線並開始」。模擬器依序取得／驗證該主機的憑證、檢查通道與後端即時調度、讓車隊上線；哪一步失敗就停在哪一步。路線、影像、PMS99、ETA 分頁都用同一台主機。
2. 車隊上線、訂閱成功後立刻以 `order/active` 對帳，之後每 30 秒一次。assign 漏收、重連、取消通知遺失都由對帳補回；PROCESSING 的單從模擬器本機執行存檔接回，不從頭發車。
3. 車依主系統派的單、照自己的車號執行；模擬器在「接受系統派單」模式不會自己呼叫 `order/save` 建單。

## 二 事件情境

**操作入口**：模擬器首頁「模擬控制」。分頁上方的共用頂部列選對測主機、按「連線並開始」（自動取得該主機的憑證）；首頁 11 台車各一張卡片（名單取自模擬器的車輛憑證，未上線也保留卡片），卡片上直接按「障礙物減速」「故障停車」「解除事件／復歸」，上方有「全體障礙物減速／全體故障停車／全體解除事件／復歸」；都是按一次就送，不經選單或確認對話框。全體操作在按下時固定符合條件的車，每台送一次，顯示「成功／失敗／跳過」。卡片顯示來源事件編號與 MQTT 是否送到 broker；主系統是否收錄請在即時事件管理確認（模擬器無法查證中心端）。


只開放主系統白名單裡、模擬器做得出對應行為的組合。

| 情境 | 上報（`event/report`） | 車輛行為 | 主系統應看到 |
|---|---|---|---|
| 障礙物減速 | `OBSTACLE_DETECTED`／`WARNING` | 減速到 2 m/s，持續設定的模擬秒數後恢復，訂單照跑 | 即時事件管理多一筆待確認 WARNING；訂單維持 PROCESSING |
| 路徑阻斷（故障停車） | `PATH_BLOCKED`／`CRITICAL` | 安全停車 → `vehicle_phase=FAULTED` → 車端以 REST 回報訂單 `FAULTED`（失敗退避重試）；車留在原地佔著路，預設人工復歸 | 待確認 CRITICAL 事件；該車故障；訂單 FAULTED；後車在圖台上停在故障車後面 |

- 不中斷行駛的一般告警：目前協議沒有合適的車端事件代碼，不提供，也不拿其他代碼假裝。核對結果：

  | 既有代碼／管道 | 必要欄位 | 影響 | 不能當純告警的原因 |
  |---|---|---|---|
  | `INTERLOCK_REQ`／INFO | `params.junction_id`、`action` | 只供圖台顯示等待路權 | 語意是路口路權請求，要真實路口 ID |
  | `SYSTEM_HEALTH_DEGRADED` | — | 中心端衍生 | 車端不得上報；中心只在健康回報轉 `ERROR` 時衍生，嚴重度 CRITICAL |
  | `health/heartbeat` 子系統 `WARNING` | `subsystems.*.status`、`error_codes` | 只改健康燈號 | 不產生事件紀錄 |

  最小契約修訂建議（未實作）：在[動態控制與特殊事件協議](對外介接/動態控制與特殊事件協議.md)事件矩陣新增一個車端一般告警代碼（例如 `GENERAL_ALERT`／`INFO` 或 `WARNING`，系統反應「僅告警、不影響行駛」），並在主系統 `EventCode` 白名單加入；確認後模擬器再補情境。
- 在即時事件管理「填寫確認緣由」只代表中心端已確認，不會讓模擬車復歸；車的復歸在模擬器操作。復歸不會把已 FAULTED 的訂單改回 PROCESSING。
- `event_id` 符合 `EVT-YYYYMMDD-NNNN`，同一則重送時 `event_id` 與 `timestamp` 不變（主系統以此去重）。`timestamp` 是真實 epoch 毫秒；營運（重播）時刻只記在模擬器本機紀錄。
- `location`：模擬器設定了地理參考時由事件當下的 local pose 換算；沒設時不帶這個欄位（協議允許「無值不放」），不填固定座標。
- 健康回報與事件嚴重度脫鉤（協議 §五.5）：路徑阻斷沒有硬體損壞，`health/heartbeat` 維持 OK。

隨機事件預設關閉；開啟後是「平均每 X 運行分鐘一次」，只在車真的在行駛時累積時間，每台車有自己的亂數種子，刷新與重啟不重置。

## 三 交通與速度

- 物理車速硬上限 40 km/h。倍速是營運時間倍率；telemetry `kinematics.velocity` 回報物理車速（m/s）。加速重播時圖台位置在真實一秒內前進「車速 × 倍速」，那是時間被壓縮，不是車超速。
- 全車隊共同步進：每 40 ms 模擬時間一個子步，車身 6.0×2.3 公尺（參考點後軸，與圖台錨點一致）。後車在前車／故障車後面停下，路口先佔先過、車尾離開才放行，故障車一直佔著路。
- 起點、待命格位被佔時不放、不發車；格位不夠的車不上線。這些都會顯示在模擬器「事件與阻塞」區塊。

## 四 聯測

只在本機隔離目標執行，不使用真車憑證、不對 GCP 車隊發測試事件：

```bash
cd ../syncdrive_t3_simulator
node scripts/traffic-e2e.js
```

腳本讓 PMS01～PMS03 上線，用本機主系統管理 API 建三張單（ID 以 `SIM-TRAFFIC-` 開頭），A 行駛中注入路徑阻斷、B 跟停、C 走另一條線；A 復歸後派續行單，B 從原地繼續。最後查本機資料庫比對 `security_event_logs` 與 `operation_orders`。
