## 三、兩組瀏覽帳密是互相隔離的

這是刻意設計，不是巧合：

| 情境 | 結果 |
|------|------|
| 對外入口 ＋ **內部**帳號 | **401 被拒** |
| 內部文件 ＋ **外部**帳號 | **401 被拒** |

原因是兩邊讀的是**不同的帳密檔**（`.htpasswd` 與 `.htpasswd-external`），不是
同一份檔案分權限——一邊的帳號在另一邊的檔案裡根本不存在。

而且 HTTP realm 也不同：

```
內部：WWW-Authenticate: Basic realm="SyncDrive T3 內部文件"
外部：WWW-Authenticate: Basic realm="SyncDrive T3 對外介面"
```

realm 不同代表瀏覽器**不會自動沿用**已輸入的帳密。內部人員誤點外部連結時會重新
跳出輸入框，輸入內部帳號也進不去。

## 五、VTMS 圖台目前沒有登入系統

圖台右上角的「登入帳號」是**示範帳號切換器**——用來預覽主管／一般員工看到的不同
畫面，不會驗證任何身分，也不會限制任何操作。

資料表 `accounts`、`roles`、`permissions`、`login_logs` 已經建好，但目前是空的，
後端也還沒有登入端點。權限管理屬於 **milestone 5 後勤管理層**（見
[開發進度](TP13C_2-2-4_開發進度.md)），尚未開發。

**所以圖台與內部 API 現在的實際保護只有兩層**：

1. GCP 防火牆的網段限制（80 埠只放行我方 IP）
2. 主機層的 nginx（文件與 Swagger 要帳密，圖台與 API 不要）

換句話說，**任何能連到 80 埠的人都能操作圖台、讀寫班表與地圖**。這是已知現況，
在權限管理做完之前，網段限制是唯一實質的防線。驗收項目 5-203「帳號權限控管
測試」對應的就是這一塊。

## 六、換發與維護

### 全部重新產生

刪掉憑證檔再跑 `bootstrap.sh`，它會重新產生並印出來：

```bash
cd /opt/syncdrive_t3
sudo rm -f deploy/.htpasswd deploy/.htpasswd-external \
           deploy/mqtt-credentials.txt mosquitto/config/passwordfile
sudo ./deploy/bootstrap.sh
```

同時要把 `deploy/.env` 裡對應的 `*_PASSWORD` 欄位清空，否則會沿用舊值。

### 只換一組瀏覽帳密

```bash
# 例：換對外那組
sudo sed -i 's/^EXTERNAL_AUTH_PASSWORD=.*/EXTERNAL_AUTH_PASSWORD=/' /opt/syncdrive_t3/deploy/.env
sudo rm -f /opt/syncdrive_t3/deploy/.htpasswd-external
sudo ./deploy/bootstrap.sh
```

### 更新 80 埠的來源網段

```bash
gcloud compute firewall-rules update syncdrive-web --source-ranges=<新IP>/32
```

多個位置用逗號隔開。SSH 走另一條路，改錯不會把自己鎖在外面。

### 目前的防火牆

| 規則 | 埠 | 來源 |
|------|----|------|
| `syncdrive-web` | 80 | `122.116.59.85/32`（我方） |
| `syncdrive-partner` | 3100 | `0.0.0.0/0`（廠商，靠帳密與金鑰） |
| `syncdrive-mqtt` | 1883 | `0.0.0.0/0`（車端，靠帳密與 ACL） |

3100 與 1883 目前對全世界開放。等廠商與車端的實際來源網段確定後收窄，會比現在
「有鎖但門對著大馬路」好。
