## 三、三組瀏覽帳密互相隔離

這是刻意設計，不是巧合：

| 情境 | 結果 |
|------|------|
| 廠商介接入口 ＋ **內部**帳號 | **401 被拒** |
| 技術文件 ＋ **廠商**帳號（任一組） | **401 被拒** |
| 圖台 ＋ 廠商介接帳號 `partner` | **401 被拒**（那組只管 3100 埠） |

原因是各處讀的是**不同的帳密檔**，不是同一份檔案分權限——一個帳號在別的檔案裡
根本不存在：

| 保護範圍 | 帳密檔 | 裡面有誰 |
|---------|--------|---------|
| 圖台與內部 API（80） | `.htpasswd-web` | `syncdrive`、`vendor` |
| 技術文件與內部 Swagger（80） | `.htpasswd` | 只有 `syncdrive` |
| 廠商入口（3100） | `.htpasswd-external` | 只有 `partner` |

而且 HTTP realm 也不同：

```
圖台：    WWW-Authenticate: Basic realm="SyncDrive T3 系統"
內部文件：WWW-Authenticate: Basic realm="SyncDrive T3 內部文件"
廠商入口：WWW-Authenticate: Basic realm="SyncDrive T3 對外介面"
```

realm 不同代表瀏覽器**不會自動沿用**已輸入的帳密。內部人員誤點外部連結時會重新
跳出輸入框，輸入內部帳號也進不去。

## 五、VTMS 圖台目前沒有登入系統

圖台右上角的「登入帳號」是**示範帳號切換器**——用來預覽主管／一般員工看到的不同
畫面，不會驗證任何身分，也不會限制任何操作。

資料表 `accounts`、`roles`、`permissions`、`login_logs` 已經建好，但目前是空的，
後端也還沒有登入端點。權限管理屬於 **milestone 5 後勤管理層**（見
[開發進度](TP13C_2-2-4_開發進度.md)），尚未開發。

**所以圖台與內部 API 現在的實際保護只有 nginx 的 Basic Auth 一層。**任何拿到
`syncdrive` 或 `vendor` 帳密的人，都能操作圖台、讀寫班表與地圖，而且系統無法
分辨是誰做的——沒有身分就沒有稽核。

驗收項目 5-203「帳號權限控管測試」對應的就是這一塊。做完之後圖台自己會擋人、
能分角色、能留登入紀錄，那時這道 Basic Auth 就可以退成外層而不是唯一防線。

## 六、換發與維護

### 全部重新產生

刪掉憑證檔再跑 `bootstrap.sh`，它會重新產生並印出來：

```bash
cd /opt/syncdrive_t3
sudo rm -f deploy/.htpasswd deploy/.htpasswd-vendor deploy/.htpasswd-web \
           deploy/.htpasswd-external \
           deploy/mqtt-credentials.txt mosquitto/config/passwordfile
sudo ./deploy/bootstrap.sh
```

同時要把 `deploy/.env` 裡對應的 `*_PASSWORD` 欄位清空，否則會沿用舊值。

### 只換一組瀏覽帳密

```bash
# 例：換廠商介接那組
sudo sed -i 's/^EXTERNAL_AUTH_PASSWORD=.*/EXTERNAL_AUTH_PASSWORD=/' /opt/syncdrive_t3/deploy/.env
sudo rm -f /opt/syncdrive_t3/deploy/.htpasswd-external
sudo ./deploy/bootstrap.sh
```

換廠商圖台那組時，`.htpasswd-web` 也要一起刪——它是兩份合併出來的，不刪會沿用
舊的雜湊：

```bash
sudo sed -i 's/^VENDOR_AUTH_PASSWORD=.*/VENDOR_AUTH_PASSWORD=/' /opt/syncdrive_t3/deploy/.env
sudo rm -f /opt/syncdrive_t3/deploy/.htpasswd-vendor /opt/syncdrive_t3/deploy/.htpasswd-web
sudo ./deploy/bootstrap.sh
```

### 收窄某一個埠的來源

```bash
gcloud compute firewall-rules update syncdrive-web --source-ranges=<網段>
```

多個網段用逗號隔開。SSH 走另一條路，改錯不會把自己鎖在外面。
<strong>浮動 IP 不要用這招擋自己人</strong>——IP 一換就全員連不上，那正是 80 埠
改用帳密的原因。

### 目前的防火牆

| 規則 | 埠 | 來源 |
|------|----|------|
| `syncdrive-web` | 80 | `0.0.0.0/0`（靠 Basic Auth 擋） |
| `syncdrive-partner` | 3100 | `0.0.0.0/0`（廠商，靠帳密與金鑰） |
| `syncdrive-mqtt` | 1883 | `0.0.0.0/0`（車端，靠帳密與 ACL） |

三個埠都對全世界開放，靠帳密與金鑰擋。等廠商與車端的實際來源網段確定後收窄，
會比現在「有鎖但門對著大馬路」好。
