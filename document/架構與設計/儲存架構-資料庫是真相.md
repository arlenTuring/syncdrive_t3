# 儲存架構：資料庫是真相

| 項目 | 內容 |
|------|------|
| 適用範圍 | 地圖庫、儀表板版面 |
| 變更日期 | 2026-08-27 |
| 影響 | 使用者行為與後端契約都有改變 |

---

## 一、問題長什麼樣

改好的東西存下去，重新整理之後又變回舊的。症狀出現在兩個地方：

- **地圖編輯器**：換了地圖、改了名稱，儲存後重整又跳回幾天前的版本。
- **儀表板編輯器**：調好的版面存了，跳頁再回來就被還原。

使用者的原話是「快取就是一直造成 bug 的東西」——這個判斷是對的。

---

## 二、根本原因

### 1. 地圖庫：localStorage 是真相，後端只是備份

原本的順序是「先讀 localStorage，讀不到才問後端」。於是：

- 在 A 電腦存的地圖，B 電腦看不到。
- 後端有比較新的版本時，本機的舊版仍然贏。
- 刪除只刪 localStorage，下一次補水又整份回來——使用者以為刪掉了，重整又出現。

### 2. 儀表板：範本版本號永遠對不上

版面裡有一個 `DEMO_LAYOUT_VERSION`（當時是 `114`），載入時比對「這份版面是用哪一版
範本產生的」，落後就跑一連串 `migrateXxx` 把版面補成新版。

但**後端的 plane 資料表根本沒有 `demoLayoutVersion` 欄位**。存進去的版本號在往返
之間掉了，每次讀回來都是 `0`，於是十七支範本遷移**每次載入都全部重跑一遍**，把
使用者調好的面板改回範本的樣子，然後存回資料庫。

這不是「偶爾被還原」，是每一次重整都被還原。

### 3. 防呆判斷把正常資料判成壞掉

另外有一支 `isDemoPlaneBroken`：只要「車輛分佈」或「整備分佈」缺 `dataSourceId`，
就判定整張版面壞掉，整包還原成內建快照——連使用者選的地圖一起換掉。而那個缺漏
本來就會被同一次載入裡的另一支函式補好。

---

## 三、現在的架構

> **資料庫是唯一真相。localStorage 只是快取，而且使用者一存檔就立刻更新它。**

| | 舊 | 新 |
|---|---|---|
| 開頁 | 讀 localStorage | 先畫快取（不留白），同時跟後端要，回來就覆蓋 |
| 存檔 | 寫 localStorage，順便推後端 | 寫後端；成功後才更新快取 |
| 衝突 | 本機永遠贏 | 比 `updatedAt`，**新的贏** |
| 刪除 | 只刪本機 | 連後端一起刪（`DELETE /map/library/:mapId`） |
| 後端連不上 | 無感 | 清單上標「離線」，存檔失敗會明講 |
| 範本遷移 | 每次載入重跑十七支 | **整套移除** |

### 為什麼還留著快取

只為了**不要留白**：開頁的瞬間先用上一次的內容把畫面畫出來，後端資料一回來就
整份覆蓋。它不參與決定「哪一份才對」。

後端掛掉時整個系統本來就不能運作，靠快取讓地圖編輯器單獨活著沒有意義——那是
僥倖，不是設計。

### 離開頁面要補送

儀表板的存檔是防抖的（800 ms）。原本在防抖時間內關頁、重整或跳頁，那一次 `PUT`
就沒送出去。現在 `pagehide` 與 `visibilitychange`（轉為 hidden）會把待送的版面
立刻送出。回到頁面時則重新跟資料庫要一次——但**只在沒有待送內容時**，否則會用
舊資料蓋掉還沒送出的修改。

## 四、後端契約

| 端點 | 用途 | 備註 |
|------|------|------|
| `GET /syncdrive-api/map/library` | 地圖清單 | 含 `activeMapId` |
| `GET /syncdrive-api/map/library/active` | 目前使用中的地圖全文 | 模擬器收圖資用這支 |
| `GET /syncdrive-api/map/library/:mapId` | 指定地圖全文 | |
| `PUT /syncdrive-api/map/library/:mapId` | 發布／更新 | 需 `X-Sync-Internal-Token` |
| `DELETE /syncdrive-api/map/library/:mapId` | 刪除 | 需 `X-Sync-Internal-Token`；**使用中的擋下來回 403** |
| `PUT /syncdrive-api/dashboard/planes` | 儀表板版面 | 收 `{ items: [...] }`，**整包取代** |

`PUT /dashboard/planes` 是取代語意，不是合併：送出去的就是全部。少送一張版面
等於刪掉它。

---

## 五、留下來的教訓

- **快取不能有投票權。**它可以先畫、可以撐過一次網路抖動，但不能決定哪一份是對的。
- **版本號要真的存得住。**存不住的版本號比沒有版本號更糟——它會讓遷移邏輯每次
  都以為自己遇到舊資料。
- **「幫使用者修好」要有邊界。**判定資料損壞、整包還原成內建版本，代價是使用者
  的工作沒了。缺欄位就補那個欄位，不要換掉整張版面。
