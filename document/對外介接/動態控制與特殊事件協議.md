# 動態控制與特殊事件協議 (Command & Event Protocol) 規格書

> 目前版：2026-09-18。站點以 [T3 地圖清單](T3地圖站點與路線清單.md) 為準；訂單新規格見 [錯誤與對帳](訂單API錯誤與對帳.md)。

## 一、 協議概述
本協議定位為 SyncDrive-T3 系統之「安全防護與即時介入機制」，具備全系統最高優先權，透過 **MQTT 協議** 處理非週期的指令下發與突發事件回報：
* **動態控制指令 (Commands)**：由車輛監控系統端主動下發，即時介入車輛物理行為（含門控、煞停、限速、換向），此操作不涉及目標站點或營運路徑之變更。
* **特殊安全事件 (Events)**：由車端主動偵測並觸發，回報物理衝突、邏輯違規或環境障礙，用於即時觸發車輛監控系統端告警系統並執行最低風險操作 (MRM)。

**連線認證**：車端一律連 **8883**，TLS 雙向驗證；客戶端憑證的 CN
必須等於自身 `vehicle_code`。詳見
[MQTT 通訊架構與 Topic 命名規範](MQTT%20通訊架構與%20Topic%20命名規範.md) §三。

**車輛監控系統端下發指令的實作路徑**：車輛監控系統端並非直接對 broker 發布，而是呼叫
`POST /syncdrive-api/command/execute`（需 `x-api-key`），由後端做白名單驗證、
寫入稽核紀錄後，再發布至下述 Topic。`vehicle_code` 可為單台或 `all`。
此端點屬車輛監控系統端內部介面，不對外開放。

| 類別 | 代碼 (Code) | 嚴重程度 | 觸發源 | 系統反應 (System Response) | 對其他協議之連動影響 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Command** | `EMERGENCY_STOP` | **CRITICAL** | 車輛監控系統端 | 物理煞車拉至最大，車輛鎖定靜止。 | **營運任務狀態協議**：`vehicle_phase` 轉為 `FAULTED`；訂單由車端以 REST 回報 `FAULTED` 結案（見 §五.6） |
| **Command** | `DOOR_CONTROL` | **WARNING** | 車輛監控系統端 | 遠端強制執行開門或關門動作。 | 需校驗 **營運任務狀態協議** 速度為 0 |
| **Command** | `SET_SPEED_LIMIT` | **INFO** | 車輛監控系統端 | 強制更新車載最高行駛速限參數（`limit_mps`，單位 m/s）。 | 限制 **營運任務狀態協議** 巡航速度 |
| **Command** | `SET_DIRECTION` | **WARNING** | 車輛監控系統端 | 切換前進/後退檔位 (僅限車速=0)。 | 無 |
| **Event** | `UNSCHEDULED_DOOR_OPEN`| **CRITICAL** | 車端感測 | 行駛中偵測門開，觸發緊急煞車並鎖死。| 無 |
| **Event** | `OBSTACLE_DETECTED` | **WARNING** | 車端感測 | 偵測到路徑上有異物，執行減速避讓。 | 無 |
| **Event** | **`PATH_BLOCKED`** | **CRITICAL** | 車端感測 | 路徑完全受阻無法通行，執行安全停車。 | **營運任務狀態協議**：`vehicle_phase` 轉為 `FAULTED`；訂單由車端以 REST 回報 `FAULTED` 結案（見 §五.6） |
| **Event** | **`DIRECTION_VIOLATION`**| **CRITICAL** | 定位模組 | 偵測行向偏離或逆向行駛，強制煞停。 | 無 |

## 三、 動態控制指令規格 (Commands: Center -> Vehicle)

指令透過 MQTT Topic 下發。
* **發布 Topic**: `v1/vtms/{vehicle_code}/command/execute`

### 1. 緊急停止 (`EMERGENCY_STOP`)
```json
{
  "command_id": "CMD-20260423-0001",
  "vehicle_code": "PMS05",
  "timestamp": 1713868200000,
  "action": "EMERGENCY_STOP",
  "params": { 
    "deceleration": "MAX", 
    "hazard_light": true
  }
}
```

### 2. 手動門控 (`DOOR_CONTROL`)
```json
{
  "command_id": "CMD-20260423-0002",
  "vehicle_code": "PMS05",
  "timestamp": 1713870300000,
  "action": "DOOR_CONTROL",
  "params": { 
    "door_action": "OPEN", 
    "door_id": "ALL"
  }
}
```

### 3. 臨時限速 (`SET_SPEED_LIMIT`)
```json
{
  "command_id": "CMD-20260423-0003",
  "vehicle_code": "PMS05",
  "timestamp": 1713868275000,
  "action": "SET_SPEED_LIMIT",
  "params": { 
    "limit_mps": 2.78 
  }
}
```

### 4. 強制換向 (`SET_DIRECTION`)
```json
{
  "command_id": "CMD-20260423-0004",
  "vehicle_code": "PMS05",
  "timestamp": 1713868365000,
  "action": "SET_DIRECTION",
  "params": { 
    "direction": "REVERSE" 
  }
}
```

## 四、 特殊事件上報規格 (Events: Vehicle -> Center)

事件由車端立即透過 MQTT 推播，`event_id` 為每日重置之四位數流水號。
* **發布 Topic**: `v1/vtms/{vehicle_code}/event/report`

### 1. 非正常開門 (`UNSCHEDULED_DOOR_OPEN`)
```json
{
  "event_id": "EVT-20260423-0001",
  "vehicle_code": "PMS05",
  "timestamp": 1713872100000,
  "event_code": "UNSCHEDULED_DOOR_OPEN",
  "severity": "CRITICAL",
  "location": { "lat": 25.0776, "lng": 121.2325 },
  "detail": "Illegal door opening detected during transit at 3.33 m/s"
}
```

### 2. 障礙物偵測 (`OBSTACLE_DETECTED`) - WARNING
```json
{
  "event_id": "EVT-20260423-0002",
  "vehicle_code": "PMS05",
  "timestamp": 1713872130000,
  "event_code": "OBSTACLE_DETECTED",
  "severity": "WARNING",
  "location": { "lat": 25.0778, "lng": 121.2328 },
  "detail": "Obstacle detected nearby; auto-deceleration triggered"
}
```

### 3. 路徑受阻 (`PATH_BLOCKED`) - CRITICAL
```json
{
  "event_id": "EVT-20260423-0003",
  "vehicle_code": "PMS05",
  "timestamp": 1713872180000,
  "event_code": "PATH_BLOCKED",
  "severity": "CRITICAL",
  "location": { "lat": 25.0780, "lng": 121.2330 },
  "detail": "Path fully blocked; vehicle failed to bypass"
}
```

### 4. 行向違規 (`DIRECTION_VIOLATION`)
```json
{
  "event_id": "EVT-20260423-0004",
  "vehicle_code": "PMS05",
  "timestamp": 1713872290000,
  "event_code": "DIRECTION_VIOLATION",
  "severity": "CRITICAL",
  "location": { "lat": 25.0776, "lng": 121.2325 },
  "detail": "Contra-flow or heading deviation > 135 degrees detected"
}
```

### 5. 進路聯鎖請求 (`INTERLOCK_REQ`)

> **本事件為單向顯示用，車輛監控系統端不回覆許可。**路口路權的請求與核發一律由車端與
> SCADA（號誌系統）直接完成，不經車輛行車管理系統轉發；`command/execute` 亦
> 未定義任何准許路權的指令。車輛監控系統端收到本事件只用於圖台顯示「等待路權」狀態，
> 不會因此暫停或改變營運任務進度的計算。
>
> 若營運端需要車端逐步回報路權取得過程，改以車輛監控系統端下發的 **action** 進行
> （`PUT /syncdrive-api/order/action/{actionId}`，見[車端介接說明書](車端介接說明書.md) §5.3），
> 由車輛監控系統端決定要開哪些 action、車端回報完成即可，不佔用 `task_group` 字典。
> 例如 `INTERLOCK_REQ_SEND_ACT`（已送出請求）與 `INTERLOCK_REQ_ALLOWED_ACT`
> （已獲核准）；是否實際開立這組 action 由營運端決定，目前未定案。

```json
{
  "event_id": "EVT-20260423-0005",
  "vehicle_code": "PMS05",
  "timestamp": 1713872400000,
  "event_code": "INTERLOCK_REQ",
  "severity": "INFO",
  "params": { 
    "junction_id": "J-T3-01", 
    "action": "LOCK" 
  }
}
```

## 五、 實作開發規範

1. **基礎格式約束**：全系統統一採用 13 位 Unix Epoch (ms) 作為時間戳記，且 `timestamp` 必須置於 JSON 根目錄。所有欄位值嚴格遵守 `SCREAMING_SNAKE_CASE` 命名。
2. **Ack 響應機制**：對於車輛監控系統端下發的 `Command`，車端必須在 200ms 內將確認訊息發布至 `v1/vtms/{vehicle_code}/command/ack` 並帶上原 `command_id`。
3. **門控安全互鎖**：車端接收到 `DOOR_CONTROL` 時，必須自檢車速是否為 0。若車速 > 0，則拒絕執行並於 Ack 封包中回報錯誤。
4. **單一真值源 (SSOT) 聲明**：車端為 `vehicle_phase` 與 `overall_health` 的唯一寫入源。車輛監控系統端僅做聚合與展示，嚴禁車輛監控系統端推測或逕自覆寫資料庫，以避免雙寫衝突。
5. **嚴重度與健康狀態脫鉤**：本協議 (P4) 之事件嚴重度 (`severity`: `CRITICAL`) **不等於** 設備健康協議 (P3) 之硬體損壞度 (`status`: `ERROR`)。如 `PATH_BLOCKED` 雖為 `CRITICAL`，但若無硬體損壞，健康協議仍維持 `OK`。兩者應獨立運作。
6. **狀態同步連動**：發生導致車輛受困之 `CRITICAL` 級別事件時，車端應自動將「營運任務狀態協議」中的 `vehicle_phase` 切換至 `FAULTED`。
   - `vehicle_phase=FAULTED` 與 `CRITICAL` 事件表示**車輛**故障。車輛監控系統端立即寫入告警、更新車輛故障顯示，
     既有安全處置（`EMERGENCY_STOP`、中心端取消與停止）照常有效。
   - **訂單生命週期只由車端 REST 確認**（[車端介接說明書](車端介接說明書.md) §5.2，`updateOrderProgress`）：
     車輛監控系統端不因 MQTT 故障替車端把訂單結案，只把該車進行中的訂單標示為「車輛故障，訂單結案待確認」。
     車端停止任務後須自行呼叫 `status=FAULTED`，失敗時任務保持停止並退避重試。
   - 本條取代舊版矩陣中「營運任務狀態協議：轉為 `FAULTED`」的寫法：那一欄指的是 `vehicle_phase`，不是訂單狀態。
