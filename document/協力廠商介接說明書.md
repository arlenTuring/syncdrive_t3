## 一、存取憑據

### 1.1 取得憑據

所有對外介面以 `x-api-key` 標頭認證。金鑰以帳號密碼向下列端點申請取得。

```
POST /syncdrive-api/auth/token
Content-Type: application/json
```

**請求**

| 欄位 | 型別 | 必填 | 說明 |
|------|------|:---:|------|
| `username` | String | ✓ | 提供方配發之帳號 |
| `password` | String | ✓ | 提供方配發之密碼 |
| `ttl_minutes` | Integer | | 金鑰有效時長，單位分鐘。預設 `1440`（24 小時），值域 `1`–`43200` |
| `vehicle_codes` | String[] | | 需取得 MQTT 客戶端憑證之車輛代號。未指定時回傳全部已簽發車輛 |

**回應 200**

| 欄位 | 型別 | 說明 |
|------|------|------|
| `api_key` | String | 對外介面之 `x-api-key` 值 |
| `token_type` | String | 固定為 `ApiKey` |
| `issued_at` | Integer | 簽發時間，Unix Epoch 毫秒 |
| `expires_at` | Integer | 失效時間，Unix Epoch 毫秒 |
| `expires_in_minutes` | Integer | 有效時長，分鐘 |
| `mqtt.host` | String | MQTT broker 位址 |
| `mqtt.port` | Integer | MQTT broker 埠，固定為 `8883` |
| `mqtt.tls` | Boolean | 固定為 `true` |
| `mqtt.ca_certificate` | String | 根 CA 憑證，PEM 格式。用於驗證 broker |
| `mqtt.intermediate_certificate` | String | 中介 CA 憑證，PEM 格式。客戶端憑證鏈需要 |
| `mqtt.clients[].vehicle_code` | String | 車輛代號 |
| `mqtt.clients[].certificate` | String | 該車客戶端憑證，PEM 格式 |
| `mqtt.clients[].private_key` | String | 該車客戶端私鑰，PEM 格式 |
| `mqtt.clients[].not_before` | Integer | 憑證生效時間，Unix Epoch 毫秒 |
| `mqtt.clients[].not_after` | Integer | 憑證失效時間，Unix Epoch 毫秒。等於 `expires_at` |

**範例**

```bash
curl -X POST "http://34.80.84.224:3100/syncdrive-api/auth/token" \
  -H "Content-Type: application/json" \
  -d '{"username":"<帳號>","password":"<密碼>","ttl_minutes":1440,"vehicle_codes":["PMS-01"]}'
```

```json
{
  "api_key": "9f2c…",
  "token_type": "ApiKey",
  "issued_at": 1787890000000,
  "expires_at": 1787976400000,
  "expires_in_minutes": 1440,
  "mqtt": {
    "host": "34.80.84.224",
    "port": 8883,
    "tls": true,
    "ca_certificate": "-----BEGIN CERTIFICATE-----\n…",
    "intermediate_certificate": "-----BEGIN CERTIFICATE-----\n…",
    "clients": [
      {
        "vehicle_code": "PMS-01",
        "certificate": "-----BEGIN CERTIFICATE-----\n…",
        "private_key": "-----BEGIN PRIVATE KEY-----\n…",
        "not_before": 1787889940000,
        "not_after": 1787976400000
      }
    ]
  }
}
```

**回應碼**

| 狀態 | 條件 |
|------|------|
| `200` | 簽發成功 |
| `400` | `ttl_minutes` 逾值域，或 `vehicle_codes` 含未簽發之車輛代號 |
| `401` | 帳號或密碼不正確 |

### 1.2 使用與續期

金鑰於 `expires_at` 之後失效，其後所有對外介面回應 `401`。續期方式為重新呼叫本端點取得新金鑰。

金鑰值僅於簽發回應中出現一次，提供方僅保存其雜湊值，無法回查。遺失時重新申請。

### 1.3 MQTT 客戶端憑證

車端連線採 TLS 雙向驗證：車端要確認 broker 是我方的，broker 也要確認車端是我方登錄的車輛。雙方各以憑證證明身分，連線不使用帳號密碼。車輛身分取決於憑證的 CN 欄位，其值等於車輛代號。

#### 憑證體系

系統共有四種憑證。根憑證是整套體系的信任起點，其餘三種均可循簽發關係追溯至它；伺服器憑證證明 broker 的身分，車輛憑證證明各車的身分。

| 憑證 | 簽發者 | 隨憑據下發 | 更新方式 |
|------|--------|-----------|----------|
| 根憑證 | 自簽 | 是（`mqtt.ca_certificate`） | 我方自動輪替 |
| 中介憑證 | 根憑證 | 是（`mqtt.intermediate_certificate`） | 我方自動輪替 |
| 伺服器憑證 | 根憑證 | 否，由 broker 於連線時提供 | 我方自動輪替 |
| 車輛憑證 | 中介憑證 | 是（`mqtt.clients[]`） | 每次申請憑據時重新簽發 |

**除了每日申請一次憑據之外，不需要任何其他動作。**

前三種憑證的有效期以年計，由我方在到期前自動更新，過程中已連線的車端不會斷線，也不會有需要事先安排的切換時點。每次申請憑據取得的都是當下有效的版本，照 §「連線設定」填入即可，不需要判斷我方目前處於什麼狀態。

實作上唯一需要留意的是：`ca_certificate` 欄位在根憑證輪替的過渡期間會含有**兩張**憑證。TLS 客戶端的信任錨點設定必須接受多張憑證（Node.js 的 `ca`、OpenSSL 的 `-CAfile` 皆可直接傳入），不要只取第一張。

#### 效期與更新

車輛憑證於申請憑據當下簽發，有效期等於該次申請之 `ttl_minutes`，預設 24 小時，與 API 金鑰的失效時間相同。

**每日呼叫 `POST /syncdrive-api/auth/token` 一次**，即同時取得新的 API 金鑰與新的車輛憑證。兩者不需分別處理，也不會出現其中一項先失效的情形。

根憑證與中介憑證的內容在多數時候維持不變，但在我方自動輪替時會更換。**請一律使用最近一次申請所取得的內容，不要寫死在程式或設定檔中**——寫死的話會在輪替當下連不上，而錯誤訊息只會顯示憑證無效。

#### 連線設定

TLS 連線需設定三項，各自的來源如下：

| TLS 設定項 | 內容 | 對應欄位 |
|-----------|------|----------|
| 信任憑證（`ca`） | 根憑證 | `mqtt.ca_certificate` |
| 自身憑證（`cert`） | 該車憑證，其後接中介憑證 | `mqtt.clients[].certificate` ＋ `mqtt.intermediate_certificate` |
| 自身私鑰（`key`） | 該車私鑰 | `mqtt.clients[].private_key` |

信任憑證用於驗證 broker。伺服器憑證由根憑證簽發，故設定根憑證即可完成驗證。

自身憑證需含兩張，順序為**該車憑證在前、中介憑證在後**：

```
-----BEGIN CERTIFICATE-----   ← mqtt.clients[].certificate
（該車憑證，CN 為車輛代號）
-----END CERTIFICATE-----
-----BEGIN CERTIFICATE-----   ← mqtt.intermediate_certificate
（中介憑證）
-----END CERTIFICATE-----
```

車輛憑證由中介憑證簽發，broker 須取得中介憑證方能將其追溯至根憑證。連線時一併送出，broker 即無須另行查找。

Node.js（`mqtt` 套件）之設定範例：

```js
const client = mqtt.connect({
  host: access.mqtt.host,
  port: access.mqtt.port,
  protocol: 'mqtts',
  ca: access.mqtt.ca_certificate,
  cert: vehicle.certificate.trimEnd() + '\n' + access.mqtt.intermediate_certificate,
  key: vehicle.private_key,
});
```

## 二、通訊通道

| 通道 | 協定 | 埠 | 認證 | 用途 |
|------|------|----|------|------|
| REST | HTTP/JSON | `3100` | `x-api-key` 標頭 | 任務內容拉取、狀態回報、計畫與預測資料讀取 |
| MQTT | MQTT 5 over TLS | `8883` | 客戶端憑證 | 任務指派、車輛狀態回報、控制指令 |

REST 通道之基底路徑為 `/syncdrive-api`。

## 三、共通資料表示法

### 3.1 時間

所有時間欄位為 **Unix Epoch 毫秒**（13 位整數）。

計畫時刻（班表排定之時刻）以營運當地時間 `Asia/Taipei` 計算後轉為 Epoch。

部分欄位源自資料庫 `bigint` 型別，以**字串**形式回傳（如 `plannedStart`、`plannedEnd`）。運算前需先轉為數值。

### 3.2 座標

位置欄位單位為**公尺**，採場域參照座標系：X 軸向東為正，Y 軸向北為正。

場域範圍與各停靠點座標載於[車端介接說明書](車端介接說明書.md) §四。

### 3.3 識別碼

| 識別碼 | 格式 | 範例 |
|--------|------|------|
| 車輛代號 `vehicle_code` | `PMS-` ＋ 兩碼數字 | `PMS-01` |
| 班次代碼 `trip_code` | 路線代號 ＋ `HHMM` | `ST0115` |
| 訂單編號 `order_id` | `YYMMDD-` ＋ 班次代碼 | `260828-ST0115` |
| 停靠點 `station_id` | `station_` ＋ 序號 | `station_4` |
| 渡線途經點 | `xo_` ＋ 渡線序號 ＋ 端點 | `xo_1_a` |

狀態碼、任務名稱與動作代碼一律採 `SCREAMING_SNAKE_CASE`。

### 3.4 錯誤回應

| 狀態 | 條件 |
|------|------|
| `400` | 參數格式或值域不符 |
| `401` | `x-api-key` 缺少、不正確或已過期 |
| `404` | 資源不存在 |
