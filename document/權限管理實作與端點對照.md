# 權限管理實作與端點對照

## 認證與資料

- 瀏覽器使用 `syncdrive_session` HttpOnly Cookie；寫入另驗證 `syncdrive_csrf` 與 `x-csrf-token`。
- 未登入回應 401，已登入但缺權限回應 403。權限由帳號所有角色的權限聯集即時查詢。
- 固定開發管理員為 `syncdrive`；啟動時只補齊該帳號與內建最高管理員權限，不覆寫一般角色。
- 車端／合作方的 External API Key、MQTT 與模擬器營運時鐘維持原認證邊界，不套用瀏覽器 Cookie。

## 已登錄但尚未接業務入口

權限目錄以 `connected: false` 明示下列項目尚未完成後端業務授權，不應視為已驗收：虛擬圍籬 CRUD、站點／設備 CRUD、服務管理全頁、媒體分組／排程／訂單紀錄、事件管理、整備任務複製。月台門／載具控制目前只有監看資料流，尚無由瀏覽器送出控制命令的既有端點。

## Migration、部署與回復

1. 先備份資料庫，套用 `backend/src/database/migrations/20261011-access-control.sql`，再套用 `20261012-role-permissions.sql`。兩者可重複執行；若既有角色名稱去除空白後重複，第二支會列出衝突並停止。
2. 啟動後端後，權限字典依穩定代碼 upsert；只有內建最高管理員補齊完整權限。
3. 建置：後端與前端各執行 `npm run build`。登入後由「權限管理模組」進入帳號或角色頁。
4. 回復程式可切回前一版 commit；資料表與新增權限列可保留，不影響舊版。若必須回復 DB，應從步驟 1 的備份還原，不直接刪除角色、帳號或稽核紀錄。
