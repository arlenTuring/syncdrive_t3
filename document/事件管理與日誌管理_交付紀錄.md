## 二 權限代碼

| 代碼 | 用途 |
| --- | --- |
| `events.events.view` | 事件資訊清單、歷史事件、事件詳情、回放時間窗 |
| `events.events.manage` | 人工確認（只改中心端閱覽狀態） |
| `events.events.export` | 事件報表 CSV |
| `events.video.view` | 影像監控管理、事件回放的影像側 |
| `logs.system.view`／`logs.system.export` | 系統操作紀錄 |
| `logs.permissions.view`／`logs.permissions.export` | 權限異動查詢 |
| `logs.operations.view`／`logs.operations.export` | 營運操作紀錄 |
| `logs.authentication.view`／`logs.authentication.export` | 登入登出紀錄 |

- 只有「最高管理員」角色在後端啟動時自動補齊；其他角色不會被擴權。部署設定的廠商角色預設不含日誌權限。
- 日誌 API 類別守衛只確認「至少能看一類」，每個請求再檢查該類別自己的 view／export。
- 通用 SQL 資料來源（`POST /datasource/query`）禁止讀 `login_logs`、`operator_action_logs`、`permission_change_logs`、`accounts`、`account_sessions`、`account_roles`、`roles`、`role_permissions`、`permissions`、`partner_api_keys`，避免繞過日誌權限讀到資料。資料管理的 SQL 主控台（`system.data-admin.execute`）仍可讀全部，屬系統管理員權限。
- Socket：`invalidate` 房間只送無敏感內容的失效訊號；事件推播在專屬 `events` 房間（需 `events.events.view`）。每 30 秒重新驗證 Session 與權限，登出、停權即斷線，權限撤銷即退出房間。

## 三 稽核涵蓋範圍與分類

對照表在 `backend/src/audit/audit-catalog.ts`。修改型 API 以 `@AuditAction(代碼)` 標註，由全域 `AuditInterceptor` 寫入；操作者一律取後端 Session（外部整合記 `external-api`），不接受 body 的 operatorId。

- 系統操作紀錄（SYSTEM）：系統基礎設定、SSL 憑證、監測門檻、圖資儲存／刪除／啟用／發布、載具模型與地圖載具設定、載具註冊／修改／服務範圍／移除、媒體／媒體分組／媒體排程、儀表板、資料來源、資料查詢與清理、保存政策、即時資料重置、事件與日誌匯出。
- 營運操作紀錄（OPERATIONS）：班表建立／修改／刪除／複製／發布／部署、時間模板、整備任務、班表調整申請／審核、派遣日計畫、營運時鐘、即時派遣開關、營運任務建立／進度／取消、站點動作回報、降級計畫與執行／取消／參數／內容／解除、控制指令（速限、方向、緊急停車等）、事件人工確認。
- 權限異動（`permission_change_logs`）與登入登出（`login_logs`）沿用專用表，不在操作紀錄重複計數。
- 結果：成功 SUCCESS；400／403／404／409 等被拒 REJECTED；其他錯誤 FAILED。守衛擋下的請求（例如無權限 403）不會進入攔截器，不另記。
- 內容只存遮蔽後的摘要（預設只記變更了哪些欄位名稱）；密碼、雜湊、token、API key、cookie、session、CSRF、私鑰一律遮蔽。
- 交易：事件確認、權限異動與其稽核同一交易提交。攔截器寫入在操作完成後，無法與業務同交易；寫入失敗會計數並記錯誤，不影響已完成的操作（含車控），也不重送任何指令。
- 查詢日誌與事件不產生日誌；匯出記一次。

## 七 GCP 部署步驟

1. 推上 `main` 後執行 `./deploy/sync.sh`（流程不變）。預期 Migration 顯示待執行 2 支：`20261020`、`20261021`。
2. 部署完成後，最高管理員登入，於「角色管理設定」為需要的角色勾選事件與日誌權限（其他角色不會自動取得）。
3. 「其他大量紀錄」保存政策之後不再刪事件；如需清理事件，於「資料管理 → 保存政策」設定新的「事件紀錄」類別（預設停用）。
4. 影像：依 `影像監控與歷史錄影_交付紀錄.md` 第七節部署（`VIDEO_PROVIDER` 已移除）。

回退：程式可回到前一版；新增欄位與索引都是向後相容的，可保留不刪。`operator_action_logs.action_type` 已改為 varchar，舊程式寫入的值仍相容。
