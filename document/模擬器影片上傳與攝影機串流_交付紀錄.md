# 模擬器影片上傳與攝影機串流：交付紀錄

依據：`document/模擬器影片上傳與攝影機串流_Claude_Code實作指示.md`。
本文件是工程交付紀錄；尚未驗證的項目列在第七節。

## 一 做了什麼

使用者在模擬器（`../syncdrive_t3_simulator`）上傳一個影片，綁到載具的攝影機通道（例如 PMS01／front），按「啟動串流」後，模擬器就像一支真的 RTSP 攝影機。主系統用既有的「設定影像來源」拉流、即時監看、錄影，也能在歷史頁查詢。整個過程不用開 terminal 跑 ffmpeg。

```text
瀏覽器上傳 → 模擬器 Node（127.0.0.1:4300）→ data/video（原檔＋相容檔，UUID 檔名）
  → ffmpeg 以真實時間 1× 推流（RTSP/TCP，發布帳號只在模擬器內）
  → 模擬器攝影機服務（MediaMTX 1.21.2，容器 syncdrive_sim_video，RTSP 18554，不錄影）
  → 主系統媒體服務依來源設定拉流（讀取帳號）→ WebRTC／HLS、fMP4 錄影、hook 索引、歷史頁
```

邊界：
- MQTT 沒有新增任何影像 topic。
- 模擬器不讀主系統的資料庫，不寫主系統的錄影空間，不送 hook，也不建 `vs_`／`vt_` 路徑。
- 兩個媒體服務是不同容器，帳號與儲存都分開。

## 三 使用步驟（一個影片 → PMS01／front → 主系統歷史）

1. 模擬器控制頁 → 「影像串流」→ 「攝影機服務」，選這台電腦的區網 IP，按「儲存對外主機」。
2. 在「影片庫」選檔後按「上傳」。上傳時看得到進度，也能取消。上傳完成後會自動轉成相容格式，「相容檔」欄顯示「已就緒」。
3. 在「影像通道」選影片，載具填 `PMS01`、攝影機名稱填 `front`，按「新增通道」，再按「啟動串流」。狀態變成「發布中」即可。
4. 按「主系統來源設定」，再按「取得測試讀取密碼」。
5. 主系統登入後到「影像監控」，點格子的「設定影像來源」→ 建立新來源 →「分欄輸入」，依模擬器顯示填入：

   | 欄位 | 值 |
   | --- | --- |
   | 協定 | rtsp |
   | 主機 | 模擬器顯示的區網 IP |
   | 連接埠 | 18554 |
   | 路徑 | /sim/pms01/front |
   | 帳號／密碼 | sim-read 與讀取密碼 |
   | 載具 | PMS01 |
   | 攝影機識別 | pms01-front |
   | 錄影品質 | 原始 |

6. 先按「測試連線」，看到畫面後再儲存。「儲存錄影」保持勾選。
7. 格子會開始即時播放。一兩分鐘後，「歷史影像查詢」就查得到這段錄影。

## 五 主系統整合的對應紀錄（`verify-simulator.cjs`，分段 20 秒）

| 項目 | 值 |
| --- | --- |
| 模擬器通道 | `/sim/pms01/itest-mvfjex8b`；影片 av1.mkv（5 秒，循環） |
| 主系統來源 | sourceId `3febe027-5767-48c1-a060-e70ec70d2982`；revision `510d5789-46f1-4471-acf8-4dcea65ac39f`；mediaPath `vs_510d578946f14471acf84dcea65ac39f`；載具 PMS01 |
| 錄影片段 | 2026-10-19T17:37:46.377Z → 17:38:08.110Z；17:38:08.106Z → 17:38:28.773Z（相鄰、無缺段，跨過多次檔尾循環） |
| 停止期間缺段 | 2026-10-19T17:38:33.505Z → 17:38:54.444Z（真實缺段，不補幀） |

逐項通過：
- 模擬器確認有影像。
- 來源欄位使用區網 IP、original、center。
- 127.0.0.1 仍被主系統擋下（SSRF 沒有放寬）。
- 主系統「測試連線」取得 H.264，回應不含密碼。
- 兩格指向同一來源，只建立一條媒體路徑。
- 來源連線中且錄影中，模擬器看得到主系統在讀取。
- 主系統媒體服務有 HLS（播放器的備援路徑）。
- 錄影：兩段實體檔都可解碼（H.264、有影格）。
- 歷史：manifest 有片段，Range 請求回 206。
- 中斷：模擬器停止後來源顯示未連線；重新開始後有新錄影，時間軸顯示缺段。
- 取消錄影需求後：媒體服務停止錄影、沒有新片段、舊錄影保留，即時串流照常。

## 六 負載量測（720p、15 fps、約 1.6 Mbps；每路都是獨立通道與獨立來源）

| 路數 | 通道就緒 p50 | 主系統連線 p50／p95 | 推流 fps | 錄影解碼 fps | 推流 ffmpeg 合計 CPU | 模擬器攝影機服務 | 主系統媒體服務 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 0.79 s | 23 ms | 15.1 | 15 | 0.3% | 0.7%／33 MB | 1.3%／77 MB |
| 2 | 0.78 s | 43 ms | 15.1–15.2 | 15 | 0.5% | 1.3%／33 MB | 1.8%／75 MB |
| 12 | 0.79 s | 111／131 ms | 14.4–15.1 | 15 | 1.6% | 5.6%／36 MB | 4.4%／105 MB |

讀數說明：
- **CPU 很低**：推流是 stream copy，不重新編碼。
- **CPU 單位**：百分比是單核的百分比。
- **連線時間**：「主系統連線」是在測試程序內呼叫 reconcile 量到的，包含輪詢間隔。
- **檔案沒有複製**：12 路共用同一份相容檔，影片庫大小沒有增加。

## 七 尚未驗證

- **瀏覽器實際首幀**：主系統畫面要登入，需由使用者在瀏覽器操作。本次驗到主系統媒體服務產生 HLS、錄影可解碼，但沒有量測主系統播放器 WebRTC 的首幀時間，也沒有截圖。模擬器頁面已在內建瀏覽器確認：狀態、來源設定表、啟動串流都正常。
- **瀏覽器選檔上傳**：自動化工具無法操作檔案選擇器，上傳改以相同 API（multipart）驗證。
- **有聲音的通道**：沒有驗證 HLS 的聲畫同步。WebRTC 不一定支援 AAC，所以不承諾 WebRTC 有聲音。
- **GCP**：沒有在 GCP 驗證，也沒有 VPN 環境。家用 NAT 後面的模擬器，GCP 主系統拉不到它的 18554。要用同 VPC／VPN，或把模擬器的攝影機服務放到 GCP 拉得到的測試主機。本機可拉，不代表 GCP 可拉。
- **環境與瀏覽器**：12 路只在這台 Mac 跑過，沒有在目標主機量測；Safari／Edge 沒有測。
- **影像跟隨模擬營運時鐘**：不支援。影像一律以真實時間 1× 播放，要驗事件與軌跡對齊時請用 1×。
