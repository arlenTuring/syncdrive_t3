# 影像資源管理與即時影像監控：交付紀錄

依據：`document/影像監控標籤頁與歷史錄影_Claude_Code實作指示.md`（影像唯一有效的製作指示）。本文件記錄本次重整的實作、資料升級規則、權限與稽核對照、操作說明、測試結果與尚未驗證的項目。先前的 `影像監控與歷史錄影_交付紀錄.md` 只代表當時結果。

## 一 兩個頁面

| 頁面 | 側欄可見條件 | 內容 |
| --- | --- | --- |
| 即時影像監控（原「影像監控管理」） | `events.video.view` | 使用者自訂的監控標籤頁、編輯版面對話框（1–12 格、拖拉縮放）、格內選來源、播放、臨時全螢幕 |
| 影像資源管理（取代原「歷史影像查詢」入口） | `events.video.configure`、`events.video.recording-manage`、`events.video-history.view` 任一 | 來源清單（分頁、篩選、真實狀態）、啟停、新增／編輯／一鍵複製／刪除、來源標籤、儲存錄影、歷史錄影子畫面、進階設定（全域預設與連線範圍、錄影儲存設定） |

相容性：
- **舊頁面與連結**：舊的 `video-history` 頁面 ID 會導向影像資源管理。事件回放的「在影像資源管理的歷史錄影開啟」、舊的 `openVideoHistory()` 呼叫，都會直接進歷史錄影子畫面，並保留來源、時間窗與 eventId。
- **只有歷史權限的帳號**：進影像資源管理時只看得到「查詢歷史錄影」，不會讀到任何來源連線。

## 二 主要規則與實作

### 錄影以來源為準

- 錄影需求的條件是 `enabled && recording_enabled && 未刪除`，與是否放進監控格、是否開著網頁無關。
  - 實作：`VideoConfigService.recordingDemand()`、`VideoReconcilerService`。
- 格子的 `recording_requested` 保留為 deprecated，不再影響錄影。
- 舊的整頁格子保存 `PUT /tabs/:id/tiles` 改回 400 `CONTRACT_CHANGED`。
- 空間不足時保留來源設定，實際狀態顯示「錄影暫停：空間不足」。

### 來源

- **標籤**：最多 10 個、每個 30 字；全半形、大小寫、連續空白不同的視為同一個。
- **只改名稱、標籤、啟用或儲存錄影**：不建立新版本、不重啟串流。改連線或鏡頭關聯才建立新版本。
- **一鍵複製**：
  - 產生新的 sourceId、revision 與媒體路徑；密碼在伺服器內重新加密。
  - 名稱為「原名稱的複製」，原名稱太長時截短原名，保留完整後綴。
  - 不複製歷史、狀態、播放授權或工作。
  - 以 `requestId` 冪等：同一個請求重送不會建立第二份；明確再按一次才會再複製一份。
- **刪除**：停用＋soft delete。刪除前列出引用的標籤頁與格子數、是否會停止錄影。格子保留位置與綁定，顯示「來源已刪除」，可以重新選來源。錄影保留，可從歷史錄影查詢。
- **背景健康探測**：
  - 適用對象是啟用、但沒人看也沒在錄影的 RTSP／RTSPS 來源。
  - 每 30 秒一輪，每輪最多 60 個、同時 3 個，各自 4 秒逾時；只送 DESCRIBE，不拉串流。
  - 錄影中或有人在看的來源，直接以媒體服務的實際接入判斷。
  - 狀態每 30 秒刷新一次，超過 90 秒沒更新就是「狀態待更新」，不沿用上次的綠燈。
- **單一來源出錯不影響其他來源**：之前只要一個來源的設定被媒體服務拒絕，例如只有帳號沒有密碼，整輪同步就失敗，所有來源都顯示「影像服務無法連線」。
  - 現在只標示那個來源有錯，其他來源照常。
  - 只有帳號、沒有密碼時，改用 `user:@host` 的寫法。

### 監控版面

- **座標與比例**：
  - 座標是 0–10000 的正規化整數，每頁另存畫布比例，初值 16:9。
  - 監看時整個畫布等比例縮放，不依格數重排；影片大小不參與版面計算。
- **加格**：第一格滿版，第二格左右各半。第三格起分割選取的格子，沒選就分割面積最大的一格；較寬左右切、較高上下切，其他格子不動。「平均重排」要使用者按下才會執行。
- **拖拉與縮放**：從格子標題列拖曳移動，從邊或角拉伸大小，放開時對齊 1% 格線並吸附到其他格子的邊。越界、太小、重疊就回到最後合法位置。
- **前後端檢查**：前端與後端都會檢查越界、NaN、負尺寸、最小 500、重疊、重複或跨頁的 tileId、第 13 格。
- **儲存**：
  - 版面儲存：`PUT /tabs/:id/layout`。名稱、比例與增刪改格子在同一交易完成，用標籤頁版本防止互相覆蓋。
  - 換來源：`PATCH /tabs/:id/tiles/:tileId/source`，使用格子自己的版本，所以版面與綁定互不覆蓋。
- **格子顯示**：
  - 影片用 `object-fit: cover` 填滿格子、置中裁切，標題列固定高度，播放區設 `min-width/min-height: 0` 與 `overflow: hidden`。
  - 沒有來源的格子，直接在格內顯示可搜尋、依來源標籤分組的下拉選單。
  - 已綁定的格子，右上角「設定」只能重新選來源或清除綁定。

### 監控標籤頁整體全螢幕（2026-10-21）

- **入口**：目前標籤頁工具列的「全螢幕」按鈕，以及每個標籤頁「更多」選單的「此標籤頁全螢幕」（會先切到該頁）。只要能看即時影像就能用，不需要設定權限。
- **對象**：對同一個監控容器呼叫 `requestFullscreen()`。容器內有標籤名稱、「離開全螢幕」、全部格子；不含應用側欄、頁首、標籤列與編輯工具。不是放大單一鏡頭，也不另開頁。
- **版面**：仍用該頁保存的正規化座標與畫布比例，依全螢幕容器內的畫布區（ResizeObserver）重新等比例 fit、置中；全螢幕時取消一般模式的 640 px 最小寬度。所有格子同時可見，畫布外可能留黑邊，不拉伸、不重排。
- **播放**：進出只改容器樣式，播放器與播放授權不重建、不重取，音訊與來源維持；錄影不受影響。
- **狀態來源**：以 `document.fullscreenElement` 與 `fullscreenchange` 為準（Esc、瀏覽器退出都會正確還原）；`requestFullscreen` 被拒時顯示「無法進入全螢幕」，不顯示成已全螢幕。不攔截瀏覽器的 Esc。
- **網頁滿版備援**：瀏覽器不支援原生全螢幕時，同一容器改用固定定位填滿視窗，頂部標明「網頁滿版（瀏覽器工具列仍會顯示）」，Esc 可退出。
- **單格**：整體全螢幕中按某格的放大，在容器內暫時放大該格（其他格隱藏但不停播），「返回整頁」回到整體畫面，不再要求第二層原生全螢幕。一般模式的單格原生全螢幕維持原樣。
- **浮層**：格內來源設定對話框與通知放在全螢幕容器內；共用 `AnchoredPopover` 在有原生全螢幕時改掛到全螢幕元素內，下拉不會被瀏覽器 top layer 蓋住。
- **其他**：全螢幕時不能拖曳版面（編輯版面仍走對話框，要先離開全螢幕）。離開頁面（切換頁、登出）時只退出這一頁自己的全螢幕。全螢幕不寫入資料庫、不修改版面或錄影，下次進頁也不會自動進入。

## 三 資料升級規則（migration `20261024-video-resources-and-layout.sql`）

1. **`video_sources.recording_enabled`**：
   - 新來源預設 true。
   - 既有來源依舊格子回填：只要有效格子中任一 `recording_requested AND enabled` 就是 true；沒有任何有效格子則是 false。這樣升級後不會突然替從未要求錄影的來源開始錄影。
   - `enabled=false` 的來源同樣保留算出的保存意圖。
2. **`video_sources.tags`**：既有來源設為 `[]`，並加檢查約束（陣列、最多 10 個）。
3. **`video_sources.request_id`**：一鍵複製的冪等鍵，非空值唯一。
4. **監控標籤頁**：新增 `canvas_aspect_ratio`（初值 1.7778，範圍 0.25–4）與 `layout_schema_version`。
5. **格子座標 `x/y/w/h`**：依舊版寬螢幕的固定欄數回填（1 格 1 欄、2–4 格 2 欄、5–9 格 3 欄、10–12 格 4 欄），保留 tileId、sourceId、頁序與頁名。格數範圍外、從未顯示過的殘留格子刪除。
6. **格子位置唯一約束**：改為 `DEFERRABLE INITIALLY DEFERRED`，版面儲存可以在同一交易內交換位置。
7. **可重跑**：已列入 `deploy/migrations/order.txt`、`deploy/migrate.sh`（順序檢查、ledger 一致性檢查）與 `deploy/migrations/README.md`。
   - 本機實際套用兩次結果一致。
   - 套用後以 TypeORM schema builder 比對，只剩預設值表示法的差異，沒有欄位或約束差異。
8. **部署順序**：`sync.sh` 的流程是先停 backend 與媒體 worker、跑 migration、再啟動新版，新舊兩套錄影需求算法不會同時運作。

## 四 權限與稽核

| 動作 | 權限 |
| --- | --- |
| 看監控版面、播放、安全來源選項 | `events.video.view` |
| 改版面、格子綁定、新增／編輯／啟停／複製／刪除來源、全域預設、連線範圍 | `events.video.configure` |
| 讓來源儲存錄影：新增時預設勾選、複製會錄影的來源、切換儲存錄影 | `events.video.recording-manage`；缺權限就整個拒絕，不偷偷改成不錄 |
| 只有錄影管理權限的人 | 只能改「儲存錄影」，不能動連線與其他設定 |
| 歷史查詢、下載、刪除 | `events.video-history.view`／`.export`／`.delete`（不變） |

- **權限宣告方式**：每個 API 方法都明確標示權限；方法上的設定會取代類別預設，所以只有歷史權限的人不會被類別預設擋住。
- **新增稽核代碼**：
  - `VIDEO_SOURCE_DUPLICATE`（複製來源）
  - `VIDEO_SOURCE_ENABLE`（啟用／停用來源）
  - `VIDEO_LAYOUT_SAVE`（儲存監控版面）
  - `VIDEO_TILE_BIND`（變更監控格子的來源）
- **稽核內容**：記 actor 與 source／tab／tileId，不記密碼；不記拖曳過程或輪詢。

## 五 操作說明

1. **新增攝影機**：
   - 到「影像資源管理」按「新增來源」，填名稱、來源標籤與連線（分欄或完整網址）。
   - 先按「測試連線並預覽」，確認畫面後再新增。
   - 「儲存錄影」預設勾選，來源啟用就由伺服器持續錄影。
2. **清單操作**：
   - 開關直接啟停來源。
   - 「複製」會立刻在原來源下方建立「…的複製」。
   - 「歷史錄影」進該來源的歷史子畫面。
   - 「刪除」會先列出影響，確認後才刪。
3. **進階設定**：工具列的「全域預設與連線範圍」「錄影儲存設定」。全域預設要先預覽每個來源的變更，確認後才套用。
4. **建立監控版面**：
   - 到「即時影像監控」按「新增標籤頁」，填名稱、按「加入影像格」。
   - 拖曳格子標題列可移動，拉邊或角可調整大小，最後按「儲存版面」。
   - 之後要修改，用「編輯版面」或標籤頁選單。
5. **綁定來源**：在空格的下拉搜尋並選擇來源，就開始播放。已綁定的格子按右上角「設定」換來源或清除。
6. **整頁全螢幕**：在「即時影像監控」按工具列「全螢幕」，或標籤頁「更多」選單的「此標籤頁全螢幕」。按 Esc 或「離開全螢幕」退出；全螢幕中按某格的放大可暫時放大單格，「返回整頁」回到整體畫面。

`verify-resources.cjs` 涵蓋：
- 錄影權限：沒有錄影管理權限時，新增預設儲存錄影的來源被整個拒絕。
- 標籤去重；只改名稱或標籤不建立新版本。
- 清單篩選與分頁；狀態帶 stale。
- 啟停的版本檢查。
- 錄影需求以來源為準（沒綁格子也錄）。
- 一鍵複製：新路徑、重新加密、冪等、名稱長度、版本與權限；改副本不影響原來源。
- 版面：分割、移動、刪格，拒絕重疊、不屬於這頁的 tileId、0 格與 13 格；綁定用格子自己的版本；停用來源不能綁定；舊 API 回契約錯誤。
- 刪除來源：影響預覽，格子保留綁定，安全選項不含連線資訊。
- 健康探測：連得上的判為在線，連不上的判為離線並附原因。

測試期間的環境說明：
- **網路**：這台 Mac 改用手機熱點（172.20.10.2）。另一個專案的 Docker 網路 `accsys-test_default` 使用 172.20.0.0/16，容器因此連不到這個 IP。整合測試改用這台 Mac 的 `bridge100` 位址 192.168.64.1（容器與主機都連得到，也在預設連線範圍內）。主系統的連線範圍設定沒有修改，模擬器的對外主機測完已還原。
- **儲存政策**：本機磁碟剩餘低於自動最低保留，所以本機錄影平時是暫停的。測試期間暫時放寬政策並暫停背景壓縮，結束後已還原。

## 七 尚未驗證

- **瀏覽器實機操作**：產品頁面需要登入，自動化不能代為輸入密碼。下列項目要在使用者登入後實測：版面拖拉與縮放、吸附、不合法位置回彈、格內分組下拉、cover 填滿（直式、橫式、超寬影片）、全螢幕、歷史子畫面的返回與條件保留、只有歷史權限的帳號看到的畫面。
- **角色實機**：各角色（live-only、configure、recording-manage、history-only、export／delete）的 UI 與 Socket 實際行為，目前只在 API 與服務層驗證。
- **未實作的錄影品質選項**：轉碼品質「平衡／節省空間」與共用 H.264 proxy 仍未實作；來源對話框只顯示「原始」，沒有把未完成的選項當成可用。
- **既有限制**：GCP 網路（WebRTC ICE、GCS）、12 路目標主機、Safari／Edge，同 `影像監控與歷史錄影_交付紀錄.md` 第八節。
