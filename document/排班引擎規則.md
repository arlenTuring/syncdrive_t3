# 排班引擎規則

更新日期：2026-07-24

適用程式：`frontend/src/features/shift-list/utils/schedule-engine`

產品入口：[概覽](排班引擎概覽.md)。公式與完整代號：[規格](排班引擎規格.md)。


## 一 規則優先順序

引擎排班時依下列順序處理

1. 車輛必須完成整輪路線
2. 同車不得重疊
3. 同車必須保留恢復與換線時間
4. 回程必須在整備切入餘裕內完成
5. 同方向發車必須符合班距
6. 在以上硬約束內優先維持正線服務連續與目標 PPHPD
7. 正線可占用相鄰整備頭尾 整備鎖住未被占用的邊界

如果規則無法同時成立

引擎必須撤掉尚未成輪的去程

不得留下只有去程的車輛

不得硬塞一個違規回程


## 二 完整路線鐵則

每台車都必須依路線群組的執行順序完成一整輪

兩條路線的例子

下行之後必須接上行

只有下行沒有上行不算完成

一台車進入整備或收班前

正線趟數必須是路線數的整數倍

如果回程可以合法排入

引擎補上回程

如果回程不能同時符合班距 空檔與整備期限

引擎撤掉該輪尚未完成的去程


## 三 路線執行順序

同一台車必須依 Step 4 設定的執行順序輪替

例如

下行

上行

下行

上行

不可為了方便排班而交換方向

跨整備視窗時

上一個視窗必須先完成整輪

下一個正線視窗才可以開始新一輪


## 四 一趟正線的時間

一趟占用時間包含

有效平均行駛時間（平常參考＝均）

各站停靠時間

各站靠站緩衝

計算完成後對齊 10 秒格（預設取均、向下取格）

當班距脈衝或 PPHPD 趕不上時，可把占用壓到最快行駛＋停靠（快＝下限）以補班

發車時刻也必須落在 10 秒格

例如

06:40:00

06:40:10

06:40:20


## 五 同車兩趟之間的空檔

同路線連續執行

下一趟發車不得早於

前趟結束加最低恢復時間

導通組合中段切換路線（執行順序繼任）

下一趟發車不得早於

前趟結束加前一路線換線緩衝

（恢復只在完整循環計一次，與 Step 4「均」一致）

折返繞回或非繼任換線

下一趟發車不得早於

前趟結束加最低恢復時間加前一路線換線緩衝

恢復與換線必須相加

例如

最低恢復 30 秒

換線緩衝 20 秒

折返時空檔為 50 秒；中段繼任僅 20 秒


## 六 同方向班距

班距只比較同方向相鄰兩班的發車時間

下行與下行比較

上行與上行比較

上下行各自有獨立發車序列

### 停靠點站位碰撞（硬錯誤／生成約束）

班距合格仍可能在同一停靠點撞車。規則：

1. 佔用＝該班在該站的**到站～離站**自然時間（車已到、還沒出發；本來就在該空間）
2. **不同車**的在站區間不得重疊
3. **不是**「正線末站後接充電／保養就自動繼續佔末站」——整備不在正線末站佔用模型裡
4. **生成期求解**（`enforceStationBerthConstraints`）：依發車順序預約站位 → 衝突先整趟延後 → 仍超限則依關聯圖繼任**成對**改派備用槽（TN→TNB 且圖上下一主線 NT→NTB；**禁止** TN→NTB）→ 仍解不開才報 `STATION_BERTH_COLLISION`。完整條款見 [約束清單](排班引擎約束清單.md)。
5. 求解過程可能產生警告：`STATION_BERTH_DELAYED`、`STATION_BERTH_BACKUP_USED`

### 同一時段

相鄰同方向發車不得低於該時段班距

### 跨時段

相鄰兩班跨越時段邊界時

使用前後兩個時段中較大的班距

例如

前時段班距 180 秒

後時段班距 300 秒

跨界相鄰班距使用 300 秒

### 物理班距下限

同方向班距也不得低於車隊物理班距下限

物理班距下限為

單車最短一圈時間除以可用時間線數

結果向上對齊 10 秒


## 七 正線優先讓渡餘裕

正線優先讓渡餘裕在建立班表第二步、依整備啟用區塊分別填寫

預設為 600 秒

600 秒就是 10 分鐘

屬班表策略參數，不寫入整備任務本體

同一數值只作用在整備開頭交接邊界

正線接整備時

正線回程最晚可以在整備開始後 10 分鐘完成

整備結束時間不變

整備時長因開頭被占用而縮短

不得以同一餘裕提前結束前一整備來預出車

只有與正線視窗直接相鄰的整備可以讓渡開頭

不得跨越模板空白或其他任務

正線接整備的判斷公式

回程完成時間不得晚於

整備開始時間加整備切入餘裕


## 七之一 空時段正線讓渡餘裕

若時間模板全日有未排定時間屬性的空時段

建立班表第三步需填「空時段正線讓渡餘裕」

預設同樣為 600 秒

沒有空時段則不出現此欄位

語意只允許占用空時段開頭

正線視窗結束後

開新輪或回程最多可占用空時段開頭此秒數

禁止提前占用正線開始前空時段的尾端出車

上述兩類餘裕任一改動

都必須重新生成班表

例如

充電原定 14:00 到 15:00

餘裕 10 分鐘

回程最晚必須在 14:10 完成

如果回程在 14:09 完成

充電改為 14:09 到 15:00

如果回程要到 14:11 才完成

這一輪不得發出

引擎必須撤掉該輪去程


## 八 正線與整備

時間模板中的正線區段代表該段時間必須提供正線服務

正線視窗開始前不得為了預熱車隊而提前裁切前一整備尾端

正線優先讓渡餘裕只允許占用**接下整備的開頭**（車子來不及回來／整輪收尾需要多一點時間時，把下一段整備開始延後、鎖住整備原結束時間並壓縮時長）。

禁止用讓渡餘裕去砍**前一段整備／行前的尾巴**；也禁止為了預熱車隊而提前裁切正線開始前整備尾端出車。

行前在班表上的長度跟時間模板橫條走，不用整備任務「單次作業時長」覆蓋橫條。

### 保養尾端進場載客（載客調度）

以「該時間線真正首班正線」為錨點往回推。拓樸「設施 → 停靠」邊定義可出場站集合；引擎挑離首班起點最遠的出場站，用真實路線往回長一串載客短交路。即使首班起點本身也是出場站，仍以其他出場站的最壞距離計算（車可能停在較遠設施）。

- **時間對齊**：末段結束＝首班發車前（扣恢復／換線緩衝）；整串往前偷保養尾巴。
- **段數**：由出場站與首班起點站之間的路線距離決定；偷不過保養開始就砍掉最早那幾段。
- **載客**：計入運能（PPHPD）；不算輪替（真正首班仍是那班正線）。
- **代號**：整備代號＋路線代號＋開始時刻；色卡另一色（青綠）。
- **安全插入**：已知同路線上一班／下一班；保養尾巴只塞不會追撞的發車（與兩側間隔 ≥ 車隊物理班距下限）。由最長可達交路往短試，落地第一條時間夠且安全的串；皆不安全則不生，改由後續輪替接手。
- **適用**：僅保養（servicing）可被偷尾巴；行前／充電／機動不適用。
- **出場站過濾**：優先依整備任務 maintenance＋carWash 設施 `mapCode` 對拓樸；對不到或未填則退回全部拓樸出場站（最壞情況）。

### 行前直接接出場站首班

行前出場站由拓樸「行前設施 → 停靠」決定（通常為 T3）。

**適用條件**：該時間線在行前結束後仍有**正線**模板視窗。此時輪替相位對齊「起點＝該出場站」的路線（例如 TN／TS），直接接班，不另插進場載客。

**不適用**：行前之後該列只有機動、沒有正線。備援待命不需為了出場站強制跑某方向（例如不必特地往 N2W）；機動視窗也不轉成可派正線。

### 行前／充電／機動後調撥開輪（車站清除時間）

開輪第一腿相對「已掛、同方向上一班」的最早作動點，**不用** `max(時段目標班距, 車隊物理地板)`——那是營運服務目標，拿來當插班門檻會永遠插不進。

改用**車站清除時間**：

1. 找已經要去（或已離開）衝突站的上一班，以其在該站的發車秒為基準
2. **離開餘裕**：該站靠站／離站秒數（含靠站緩衝）
3. **遲到佔站**：上一班可能比計畫更久才騰站（均勢相對最快的差額）
4. 再加**緩衝百分比**（預設 10%）

```
earliestInsert = snap↑10s( previousDeparture + (leaveMargin + overrunHold) × (1 + buffer%) )
```

同一輪後續各腿仍守時段目標班距。充電／機動出場開輪同此規則。

### 充電／機動直接接出場站首班

充電、機動若拓樸只對到**單一**出場站，行為同行前：僅在該列之後仍有正線時，輪替相位對齊該站起點路線，不插進場載客。若對到多個出場站（位置不唯一），或不滿足「之後有正線」，則不強制相位。

機動視窗可作為正線派車窗（正線優先），前提相同：該機動開始後該列仍有正線模板。純機動列不派正線。

### 正線占用整備開頭

已合法發出的完整路線優先於整備開頭

正線占用整備開頭時

整備開始時間延後

整備原結束時間不變

整備時長縮短

其他整備任務不得跟著平移

### 服務連續

如果實際同方向班距大於時間模板目標班距

代表供給運能低於時間模板需求

若受硬約束限制仍無法補齊

必須由最終 PPHPD 趨勢與等效班距如實呈現


## 九 跨時段與整備同時發生

引擎必須同時檢查

回程物理最早發車時間

跨時段班距

回程完整占用時間

整備切入餘裕截止時間

同車下一個任務

範例

D1353 在 14:00:40 結束

恢復與換線共 50 秒

U 最早可在 14:01:30 發車

一趟占用 7 分 40 秒

物理回程時間為 14:09:10

但前一班 U 在 13:58:30

跨 180 秒到 300 秒時段後

下一班 U 最早只能在 14:03:30 發車

回程會在 14:11:10 完成

超過充電餘裕截止時間 14:10

因此不能保留 D1353

引擎必須撤掉 D1353


## 十 收班與日界

24:00 前必須完成整輪

如果末班去程找不到合法回程

撤掉尚未成輪的末班去程

不得讓車輛停在另一端


## 十一 產生流程

第一步

依每個方向與時段班距建立發車脈衝

第二步

依正線視窗與接下整備開頭讓渡餘裕建立可出車視窗

第三步

將發車掛到方向正確且可用的車輛

不得提前裁切前一整備尾端出車

第四步

檢查整輪路線與整備切入餘裕

第五步

補上合法回程

無合法回程則撤掉未成輪去程

第六步

展開正線與整備區塊；正線可壓縮整備開頭，結束時間不變

第七步

執行最終驗證


## 十二 完成條件

可用班表必須符合

沒有同車任務重疊

沒有恢復時間不足

沒有換線時間不足

沒有未完成路線

沒有低於物理下限的班距

沒有超過整備切入餘裕的回程

可行性報告必須為

`ok: true`


## 十三 錯誤與警告代號

完整表見 [規格 §4](排班引擎規格.md)。常用：

| Code | 嚴重度 | 意義 |
|------|--------|------|
| `ROTATION_CYCLE_INCOMPLETE` | error | 未完成整輪 |
| `TIMELINE_OVERLAP` | error | 同車重疊 |
| `RECOVERY_INSUFFICIENT` | error | 恢復不足 |
| `ROUTE_SWITCH_BUFFER_INSUFFICIENT` | error | 換線不足 |
| `HEADWAY_PHYSICAL_IMPOSSIBLE` | error | 班距低於物理下限 |
| `HEADWAY_BELOW_TARGET` | warning | 班距低於時段要求 |
| `STATION_BERTH_COLLISION` | error | 停靠點站位碰撞（到站～離站重疊；生成求解後仍殘餘） |
| `STATION_BERTH_DELAYED` | warning | 站位約束將班次延後 |
| `STATION_BERTH_BACKUP_USED` | warning | 站位約束改派備用路線 |
| `CLOCK_ALIGN_VIOLATION` | error | 未對齊 10 秒格 |
| `STATION_LEG_TRAVEL_INCOMPLETE` | warning | 缺拓撲 leg |
| `STATION_LEG_TRAVEL_INVALID` | error | leg 非法 |
| `TURNAROUND_LIMIT_EXCEEDED` | error | 單路線超過折返 |
| `ROUTE_ROTATION_OVER_TURNAROUND` | warning | 整輪超過折返 |


## 十四 規則服從矩陣

| 規則 | 產生階段 | 最終守門 | 不可行時 |
|---|---|---|---|
| 整備開頭讓渡 | `normalizeInput.ts`、`expand.ts` | `TIMELINE_OVERLAP` | 超過餘裕則不開新輪／撤回 |
| 完整路線輪替 | `completeRotationCycles.ts` | `ROTATION_CYCLE_INCOMPLETE` | 補回程或撤回未成輪去程 |
| 同車不得重疊 | 掛車與展開 | `TIMELINE_OVERLAP` | 不得硬塞 |
| 恢復時間 | `resolveInterTripGapSeconds` | `RECOVERY_INSUFFICIENT` | 延後、略過或撤回 |
| 換線緩衝 | `resolveInterTripGapSeconds` | `ROUTE_SWITCH_BUFFER_INSUFFICIENT` | 延後、略過或撤回 |
| 同方向班距 | `generateDepartures.ts`、`normalizeInput.ts` | `HEADWAY_*` | 不得過密補運能 |
| 10 秒格 | `physics.ts` | `CLOCK_ALIGN_VIOLATION` | 判定不可用 |
| 拓撲行駛時間 | `stationLegTravel.ts` | `STATION_LEG_TRAVEL_*` | 降級或報錯 |
| 日界完成整輪 | `completeRotationCycles.ts` | `ROTATION_CYCLE_INCOMPLETE` | 撤回未成輪去程 |

產生器必須先天遵守規則；驗證器是最後守門。
