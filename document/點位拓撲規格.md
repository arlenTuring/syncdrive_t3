# 點位拓撲規格

> 地圖「點位拓撲」定義停靠點／途經點之間的有向行駛時間與距離，供路線加總與排班逐站時刻使用。  
> 對應程式：  
> - `frontend/src/features/map-editor/types/pointTopology.ts`  
> - `frontend/src/features/map-editor/utils/pointTopology.ts`  
> - `frontend/src/features/map-editor/utils/topologyRouteTravel.ts`  
> - `frontend/src/features/shift-list/utils/stationLegTravel.ts`  
> - `frontend/src/features/shift-list/utils/buildBlockStationDepartures.ts`

更新日期：2026-07-19

---

## 1. 產品行為摘要

| 項目 | 規則 |
|------|------|
| 節點 | 地圖上的 DockingPoint、Waypoint；拓撲編輯器內另有 2D 佈局座標（與地圖公尺座標分開） |
| 邊 | **僅有向**；A↔B 最多兩條（A→B、B→A 各一） |
| 邊屬性 | 最快秒數、平均秒數、距離（公尺）；皆可暫時為空；**最快不可大於平均**，否則無法套用拓撲 |
| 途經點 | 只出現在拓撲路徑，不寫入路線 `stationIds` |
| 整線行駛時間 | 路線 avg／min **由拓撲站間加總**（唯讀）；拓撲不完整則無法儲存路線時間 |
| 節點同步 | 地圖增刪停靠點／途經點後，拓撲節點自動同步（刪節點時一併移除相關邊） |
| 排班 | 選路線時快照 `stationLegTravels`；站點時刻依 leg 權重分配實際行駛秒數；Step 4 重載目錄會刷新已選路線的 leg／avg／min |

## 2. 地圖檔 schema（`MapFileV2.pointTopology`）

`schemaVersion: 2` 的地圖檔可選欄位：

```ts
pointTopology?: {
  version: 1
  nodes: Array<{
    id: string                 // 對應 facility id
    kind: 'docking' | 'waypoint'
    label: string
    stationId?: string         // docking 必備（與站序對應）
    x: number                  // 拓撲畫布座標
    y: number
    color: string              // #rrggbb
  }>
  edges: Array<{
    id: string
    fromNodeId: string
    toNodeId: string
    minTravelTimeSeconds: number | null
    avgTravelTimeSeconds: number | null
    distanceMeters: number | null
  }>
}
```

- 省略或缺欄：解析為空拓撲（`nodes: []`, `edges: []`），舊圖可正常開啟。
- 序列化時若節點與邊皆空，可不寫入 `pointTopology` 以減少檔案體積。

路線本體仍為：

```ts
routes[].stationIds: string[]           // 僅停靠站序
routes[].avgTravelTimeSeconds?: number  // 拓撲完整時 = Σ leg 平均
routes[].minTravelTimeSeconds?: number  // 拓撲完整時 = Σ leg 最快
```

## 3. 站間路徑展開

對路線相鄰兩站 `Si → Si+1`：

1. 對應拓撲 docking 節點（`stationId` 或設施 id）。
2. 在有向圖上找最短跳數路徑（可經 waypoint）。
3. 加總路徑上各邊的 min／avg／距離。
4. 整線 = 各站間 leg 加總。

缺有向路徑、或任一邊缺時間 → `timesComplete = false`，路線編輯無法寫入有效 avg／min。

## 4. 排班如何使用 leg 時間

### 4.1 草稿欄位

`selectedRoutes[]` 增加：

```ts
stationLegTravels: Array<{
  fromStationId: string
  toStationId: string
  avgTravelTimeSeconds: number
  minTravelTimeSeconds: number
  distanceMeters?: number | null
}>
```

載入路線目錄時由作用中地圖的 `pointTopology` 展開寫入；儲存班表 body 一併持久化（快照，不隨地圖即時重算）。

### 4.2 引擎占用

```
有效平均行駛 = 拓撲 leg 完整？ Σ(leg.avg) : route.avgTravelTimeSeconds
有效最快行駛 = 拓撲 leg 完整？ Σ(leg.min) : route.minTravelTimeSeconds
一趟占用 = snap↑10秒( 有效平均行駛 + Σ 有效停靠 )
```

實作：`resolveEffectiveRouteTravelSeconds`（`stationLegTravel.ts`）。

### 4.3 班次卡站點時刻（`buildBlockStationDepartures`）

```
travelBudget = 班次卡時長 − Σ 有效停靠
站間秒數_i = travelBudget × (leg.avg_i / Σ leg.avg)   // leg 完整時
           = travelBudget / (n−1)                    // 否則均分（舊行為）
```

軟延遲拉長班次卡時，站間仍依拓撲權重等比放大，末端加總對齊 `travelBudget`。

### 4.4 可行性代號

| 代號 | 嚴重度 | 意義 |
|------|--------|------|
| `STATION_LEG_TRAVEL_INCOMPLETE` | warning | 缺 leg 或與站序不符；站點時刻回退均分 |
| `STATION_LEG_TRAVEL_INVALID` | error | leg 負值或 min＞avg |

## 5. 草稿／舊地圖遷移

| 情境 | 行為 |
|------|------|
| 舊地圖無 `pointTopology` | 視為空拓撲；既有路線 avg／min 仍可用於排班 |
| 舊路線僅有整線時間、無拓撲邊 | 路線編輯改為拓撲加總後，需補齊邊才能再存時間；排班選舊路線時 `stationLegTravels: []`，引擎用整線時間＋均分站間 |
| 舊班表草稿無 `stationLegTravels` | 解析為 `[]`；與上列相同回退行為 |
| 地圖已補拓撲、班表仍是舊快照 | Step 4 **重新進入／重載路線目錄** 時會刷新已選路線的 `stationLegTravels` 與整線 avg／min；已寫入後端的班表 body 仍須再開編輯或重選才會更新 |

建議作業順序：先在地圖編輯器完成拓撲 → 儲存／發布地圖 → 開新班表或重選路線 → 再產班。
