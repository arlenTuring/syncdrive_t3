## 1. 問題與輸入

把 Wizard 已確認的輸入編成可執行正線班表：

| 輸入 | 來源 | 用途 |
|------|------|------|
| 時間模板 | Step 3 | 時段、班距、列數、正線／整備視窗 |
| 整備任務 + `entrySlackBySection` | Step 2 | 非正線參數；讓渡餘裕（預設 600s，不寫入整備本體） |
| `emptyIntervalMainlineSlackSeconds` | Step 3 | 有空時段時；只可占用空時段開頭（預設 600s） |
| 路線群組 | Step 4 | 執行順序、leg／avg／min、停靠、靠站緩衝、換線、恢復 |
| 路線關聯圖 + 折返錨點 | Step 4 | 導通驗證通過後，決定輪替環與優先／次要繼任 |
| 折返時限 | 模板推導 | 單路線／整輪上限 |

產出：`GeneratedSchedulePlan` + `ShiftScheduleFeasibilityReport`。

生產模式：`passengerTimetableMode: 'template'`（adapter 固定）。`headway` 僅測試／次要路徑。

## 2. 硬約束與公式

### 2.1 占用（S4 + S3）

```
有效平均行駛 = stationLegTravels 完整？ Σ(leg.avg) : avgTravelTimeSeconds
一趟占用（預設） = snap↓10s( 有效平均行駛 + Σ(站停 + 靠站緩衝秒數) )（均＝平常參考）
趕班距／補運能時可壓到 snap↑10s(有效最快行駛 + 停靠)（快＝下限）
```

靠站緩衝是**固定秒數**加在各站停靠上，不是百分比。發車與到站須落在 10 秒格。到站可比拓撲平均略慢（最多約 1.3×，且至少多 10s 供對齊），不可低於拓撲最快。

### 2.2 同車空檔（S1 + S2，相加）

```
同路線：下一發車 ≥ 前趟結束 + 恢復
導通中段換線：下一發車 ≥ 前趟結束 + 前一路線換線緩衝（恢復只在折返計一次，與 Step 4「均」一致）
折返／非繼任換線：下一發車 ≥ 前趟結束 + 恢復 + 前一路線換線緩衝
```

預設恢復 30s；換線／靠站緩衝預設 0（由 Step 4 填寫）。統一函式：`resolveInterTripGapSeconds`。

### 2.3 硬輪替／導通輪替

- **完全沒有關聯圖**：舊資料才可依 Step 4 執行順序（`execution-order-ring-v1`）。
- **有關聯圖但未驗證／指紋過期**：`ROUTE_SUCCESSOR_POLICY_INVALID`，停止生成，禁止靜默退回執行順序。
- **導通驗證有效**：輪替環使用鎖定全優先路徑（`relation-graph-through-anchors-v1`）。掛車／指派／驗證共用同一 `RouteSuccessorPolicy`。

不可為求可行而任意改方向；主路線可行時不走次要／備用。每對相鄰班次必須同時符合 successor 與 terminal＝origin。

### 2.4 原子化整輪

| 模式 | 算法 ID | 成輪條件 |
|------|---------|----------|
| 執行順序環 | `rotation-cycle-completion-v1` | 趟數為路線數整數倍 |
| 導通錨點 | `rotation-cycle-through-anchors-v1` | 舊資料／工具函式相容；v2 自動生成已改為起班時原子展開整輪 |

每個起班需求在掛車時即展開完整 successor chain，不再先放去程、稍後補回程。整輪須在「整備開始 + entrySlack」前完成；放不下則記錄 `UNSERVED_SERVICE_PULSE`，不得留下半輪。

### 2.5 完整交路起班掛車（`periodic-cycle-headway-v2`）

一個脈衝代表一台車開始完整交路；同服務方向的連續 route legs 是同一班續行，不各自產脈衝。跨時段第一脈衝 ≥ 上一班 + max(舊班距, 新班距)。所有能在視窗內完成整輪的車皆可承接，避免固定相位讓單一車壟斷。整備不可為預出車而裁尾；空時段不可提前占尾端。

掛車目標：在硬約束下最大化班距脈衝承接（PPHPD）。出場／相位對齊車若僅因同方向班距被已掛班次擋住，允許**局部回推**該衝突班次及其同輪後續腿（班距讓路），再由出場車承接；回推後仍須守班距、正線視窗、完整交路與整備切入期限。讓路不可行才記 `UNSERVED_SERVICE_PULSE`（警告：表示該時段實際 PPHPD 低於目標，非班表結構硬錯誤）。

班距地板只看候選發車**之前**的同方向班次；已掛但時刻更晚的交路中段腿不抬高地板（否則行前／機動出場要從非 0 相位起班時會被未來腿卡死）。機動視窗可視為可派正線（正線優先，不代表必須占滿），但僅限「該機動開始後該列仍有正線模板」；純機動列不派正線，也不做出場相位對齊。

### 2.6 整備／空時段讓渡

| 參數 | 語意 |
|------|------|
| `entrySlackBySection` | 正線回程最多可占用「接下整備開頭」的秒數；整備結束時間不變 |
| `emptyIntervalMainlineSlackSeconds` | 僅允許占用空時段**開頭** |

正線可延後整備開始並鎖住原結束時間（壓縮時長）。不跨空白、不平移其他任務。

## 3. 流水線

```
normalizeInput（建 RouteSuccessorPolicy → 脈衝 → 掛車 → 補完 → 合併非正線）
  → assignRoutes（constraint-greedy-v1 或 route-assignment-relation-graph-v1）
  → expand
  → validate
  → plan + report
```

| 檔案 | 職責 |
|------|------|
| `normalizeInput.ts` / `generateDepartures.ts` / `completeRotationCycles.ts` | 正規化與掛車補完 |
| `routeSuccessorPolicy.ts` | 關聯圖／折返錨點 → 輪替環與繼任 |
| `physics.ts` | 空檔、占用、對齊、折返、指紋 |
| `assignRoutes.ts` | 路線指派 |
| `expand.ts` | 區塊與整備裁剪 |
| `validate.ts` | 最終守門 |
| `generate.ts` | 編排入口 |
| `../stationLegTravel.ts` 等 | 拓撲 leg／逐站時刻 |

## 4. `FeasibilityViolationCode`（完整）

語意與根因詳表見 **[可行性驗證清單](排班引擎可行性驗證清單.md)**。下表為契約速查。

| Code | 嚴重度 | 意義 |
|------|--------|------|
| `MISSING_TEMPLATE_TASKS` | error | 無可用模板任務 |
| `NO_ROUTE_FOR_TASK_TYPE` | error | 任務類型無對應路線 |
| `MISSING_TRAVEL_TIME` | error | 缺行駛時間 |
| `STATION_LEG_TRAVEL_INCOMPLETE` | warning | 缺拓撲 leg；時刻均分估算 |
| `STATION_LEG_TRAVEL_INVALID` | error | leg 非法（負值或 min＞avg） |
| `ANCHOR_CONFLICT` | error | 正線結束撞下一錨點 |
| `TIMELINE_OVERLAP` | error | 同線任務重疊 |
| `HEADWAY_PHYSICAL_IMPOSSIBLE` | error | 同方向間隔低於物理下限 |
| `HEADWAY_BELOW_TARGET` | warning | 同方向間隔低於時段要求 |
| `STATION_BERTH_COLLISION` | error | 停靠點站位碰撞（到站～離站重疊；生成求解後仍殘餘） |
| `STATION_BERTH_DELAYED` | warning | 站位約束延後發車 |
| `STATION_BERTH_BACKUP_USED` | warning | 站位約束改派備用 |
| `INSUFFICIENT_TIMELINES` | warning | 時間線數可能不足 |
| `RECOVERY_INSUFFICIENT` | error | 恢復空檔不足 |
| `ROUTE_SWITCH_BUFFER_INSUFFICIENT` | error | 換線空檔不足 |
| `CLOCK_ALIGN_VIOLATION` | error | 未對齊 10 秒格 |
| `TURNAROUND_LIMIT_EXCEEDED` | error | 單路線超過折返時限 |
| `ROUTE_ROTATION_OVER_TURNAROUND` | warning | 鎖定組合／整輪超過折返時限 |
| `ROTATION_CYCLE_INCOMPLETE` | error | 未跑完一整輪路線 |
| `MAINTENANCE_DISPATCH_UNREACHABLE` | warning | 策略略過進場載客（不安全或不達） |

`report.ok === true` 當且僅當 `errors.length === 0`。

## 6. 已知限制

1. 無整天全局回溯；允許「同方向班距讓路」之局部回推。時間線仍不足時延後／略過脈衝並如實記錄。
2. 不強制每個整點都有脈衝；交接以整備開頭讓渡與班距守門如實呈現。
3. 人工固定班次無法自動撤回時，才可能留下需人工處理的輪替衝突。
