## 開發階段 Development Phases

| 開發項目 Development Item | 說明 Description |
|---|---|
| **階段一：通訊協定與資料庫建置 / Stage 1: Protocols and Database Construction** | |
| 通訊規範設計<br>Communication Specification Design | 訂定本系統對外之通訊規範，包含連線方式、訊息格式、時間基準與資料標準處理原則。<br>Defines the external communication specification of this system, including connection methods, message formats, time base and data standardization principles. |
| 動態控制與特殊事件協議設計<br>Dynamic Control and Special Event Protocol Design | 訂定營運控制指令與特殊事件之訊息協議，涵蓋派遣調度、降級運轉及車門月台控制之下達與回覆。<br>Defines the message protocols for operational control commands and special events, covering the issuance and response of dispatch, degraded operation and vehicle/platform door control. |
| 營運任務狀態協議設計<br>Operational Mission Status Protocol Design | 訂定班次與任務狀態之訊息協議，涵蓋班次執行狀態、站點動作狀態及預估到站資訊。<br>Defines the message protocols for trip and mission status, covering trip execution status, station action status and estimated time of arrival information. |
| 設備健康與異常告警協議設計<br>Equipment Health and Alarm Protocol Design | 訂定場域設施狀態與異常告警之訊息協議，作為與 IOT SCADA 監控管理系統介接之依據。<br>Defines the message protocols for field facility status and abnormal alarms, serving as the basis for interfacing with the IOT SCADA Monitoring and Management System. |
| 車輛動態協議設計<br>Vehicle Dynamics Protocol Design | 訂定車輛運行狀態之訊息協議，涵蓋位置、速度、行駛方向、任務狀態及通訊狀態。<br>Defines the message protocols for vehicle operating status, covering position, speed, travel direction, mission status and communication status. |
| 資料庫建置<br>Database Construction | 依上述協議建立資料表結構，涵蓋主檔、營運排程、服務與訂單、場域圖資、場域與設備狀態、車輛遙測與控制指令、介面資源、帳號與權限、稽核日誌及系統基礎等十類。<br>Establishes the data table structure according to the above protocols, covering ten categories: master data, operation scheduling, service and order, field map data, field and equipment status, vehicle telemetry and control command, interface resources, account and permission, audit logs, and system base. |
| **階段二：核心軟體開發與模擬測試 / Stage 2: Core Software Development and Simulation Testing** | |
| 營運核心層開發<br>Operation Core Layer Development | 完成數據監控模組、營運管理模組、班表管理模組及事件管理模組之介面設計與程式開發，並以模擬資料驗證營運全景圖台、班表規劃部署與事件集中管理。<br>Completes the interface design and program development of the Data Monitoring, Operation Management, Schedule Management and Event Management Modules, and verifies the operation panorama dashboard, schedule planning and deployment, and centralized event management with simulated data. |
| 資源配置層開發<br>Resource Configuration Layer Development | 完成載具管理模組、場域管理模組、服務管理模組及媒體管理模組之介面設計與程式開發，建立載具、圖資、站點設施、服務路線與媒體資源之管理功能。<br>Completes the interface design and program development of the Vehicle Management, Field Management, Service Management and Media Management Modules, establishing management functions for vehicles, map data, stations and facilities, service routes and media resources. |
| 資通安全層開發<br>Communication Security Layer Development | 完成協定接入管理、外部系統整合、通訊加密服務及資料存取閘道之開發，建立對外通訊之接入、加密與存取控管機制。<br>Completes the development of Protocol Access Management, External System Integration, Communication Encryption Service and Data Access Gateway, establishing access, encryption and access control mechanisms for external communication. |
| 後勤管理層開發<br>Logistics Management Layer Development | 完成權限管理模組、日誌管理模組及系統基礎模組之介面設計與程式開發，建立帳號角色權限、稽核紀錄、系統參數與全域通知功能。<br>Completes the interface design and program development of the Permission Management, Log Management and System Base Modules, establishing account/role permissions, audit records, system parameters and global notification functions. |
| **階段三：廠測與單機測試 / Stage 3: Factory Testing and Standalone Testing** | |
| 中間檢視<br>Interim Review | 於軟體開發過程中辦理階段性檢視，確認各層模組之開發進度、介面一致性及與協議之符合性。<br>Conducts interim reviews during software development to confirm the development progress of each layer, interface consistency and conformity with the defined protocols. |
| 廠測（FAT）<br>Factory Acceptance Test | 於承包商環境內以實體設備或模擬環境辦理工廠驗收測試，驗證軟體模組功能、資料欄位定義、傳送頻率與回應時間。<br>Performs factory acceptance testing in the contractor environment using physical equipment or a simulated environment, verifying software module functions, data field definitions, transmission frequency and response time. |
| 單機測試<br>Standalone Testing | 以本系統單獨運作方式完成功能測試，確認在未介接其他子系統情況下之完整性與穩定性。<br>Completes functional testing with this system operating independently, confirming its completeness and stability without interfacing with other subsystems. |
| **階段四：跨子系統整合測試與營運 / Stage 4: Cross-Subsystem Integration Testing and Operation** | |
| 子系統間相互測試<br>Inter-Subsystem Testing | 與車輛巡航管理系統（中心端）及 IOT SCADA 監控管理系統辦理介接測試，驗證營運策略交付、執行結果回報及預估到站資訊提供。<br>Conducts interface testing with the Vehicle Cruise Management System (Center Side) and the IOT SCADA Monitoring and Management System, verifying the delivery of operating strategies, reporting of execution results and provision of estimated time of arrival information. |
| 全系統整合測試（SIT）<br>System Integration Test | 參與全系統整合測試，驗證本系統於完整場域環境中與各子系統之協同運作。<br>Participates in the system integration test to verify the coordinated operation of this system with all subsystems in the complete field environment. |
| 系統營運測試<br>System Operation Test | 依實際營運情境辦理營運測試，驗證班表部署、調度控制、事件處理及降級運轉之運作。<br>Conducts operation testing under actual operating scenarios to verify schedule deployment, dispatch control, event handling and degraded operation. |
