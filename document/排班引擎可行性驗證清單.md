## 1. 報告模型與守門語意

### 1.1 結構

每次生成或手動微調後重驗，產出：

```text
ShiftScheduleFeasibilityReport
├─ ok          ← 僅當 errors.length === 0
├─ errors[]    ← 硬錯誤；參數化模式 Step 6「下一步」要求 ok === true
└─ warnings[]  ← 警示；不單獨擋 ok，但應被審閱
```

每則 `FeasibilityIssue` 另帶：

| 欄位 | 意義 |
|------|------|
| `code` | 穩定代號（本頁主索引） |
| `severity` | `error`｜`warning` |
| `kind` | `policy`｜`limit`｜`actionable`（缺省由 code 推導） |
| `guidance` | 調整方向或「為何是極限／策略」的說明 |
| `detail` | 可選；供跳轉定位（有 `blockId` 等才可跳） |

### 1.2 產品分類（`kind`）

| kind | 介面標籤 | 專業語意 |
|------|----------|----------|
| `policy` | 策略說明 | 引擎依既定營運策略**刻意**如此處理；通常不是資料漏填 |
| `limit` | 演算法極限 | 多約束無法同時滿足；引擎已做取捨（撤班、延後、略過脈衝等），參數微調未必有解 |
| `actionable` | 可調整 | 根因多半可回溯至 Wizard 輸入或班次卡時刻，調整後通常可消除 |

### 1.3 與「跳轉定位」的關係

- **可跳轉**：`detail` 能解析出班次卡（如 `blockId`、`yardBlockId`、班距對的 `laterBlockId` 等）。
- **不可跳轉**：參數層或整表層議題（例如折返時限與鎖定組合秒數比對）。介面**不**顯示跳轉提示，避免假動作。

## 2. Wizard 前置閘門（非 FeasibilityReport）

下列檢查發生在**進入引擎生成之前**，不會寫入 `FeasibilityViolationCode`，但同屬「系統驗證」。

### 2.1 Step 4：折返錨點與排班路線組合鎖定

| 閘門狀態 | 含義 | 發生原因 |
|----------|------|----------|
| 尚未設定錨點 | 出發／折返錨點任一側為空 | 未指定真實折返判定所需的起迄站 |
| 找不到路徑 | 關聯圖上無法自出發錨點走到折返錨點 | 連線缺失，或路線起／終站未落在所選錨點 |
| 缺少全優先組合 | 僅存在含「次要」連線的路徑 | 產品要求排班只鎖定**全優先**組合；次要連線不作排班走法 |
| 超過折返時限 | 排班採用之全優先組合最快一輪 ＞ 車輛折返時限 | 組合內行駛＋停靠＋換線＋恢復已超過模板推導之時限 |
| 已鎖定 | 指紋有效且仍能算出 ≥1 條全優先路徑 | 允許進入後續步驟；引擎圖模式只走此鎖定組合 |

**設計意圖**：Step 4 不是「連通性抽樣驗證」而已，而是**設定真實折返點並鎖定引擎允許的路線組合**。指紋因關聯圖、恢復時間、行駛／停靠或錨點變更而失效時，須重新鎖定。

### 2.2 其他步驟完成條件（摘要）

| 步驟 | 典型擋關原因 |
|------|----------------|
| 1 基本資料 | 名稱空白或與既有班表重名 |
| 2–3 | 整備／時間模板未就緒 |
| 4 | 路線參數未齊、或（參數化）未鎖定全優先折返組合 |
| 5 | 已建立之行動設定欄位未填完 |
| 6 | 參數化：`scheduleOutput.feasibilityReport.ok !== true` |
| 7 | 需已有計畫可預覽 |

## 3. 引擎議題總表（依流水線階段）

嚴重度以**現行實作預設**為準；個別實例的 `message` 可能含時間線列號、路線名等動態內容。

### 3.1 輸入正規化（`normalizeInput`）

#### `MISSING_TEMPLATE_TASKS` · error · actionable

| 項目 | 說明 |
|------|------|
| **何時** | 無可用模板任務；或班距模式未能展開任何正線發車 |
| **根因** | 時間模板缺少正線視窗／有效班距，時段無法展開，或時間線／時窗過短導致零產出 |
| **營運解讀** | 引擎沒有「服務意圖」可掛載，無法進入掛車 |
| **處置方向** | 回到 Step 3 檢查正線區段、班距與模板載入 |

#### `ROUTE_SUCCESSOR_POLICY_INVALID` · error · actionable

有關聯圖但折返驗證失效、指紋過期或沒有全優先路徑時停止生成。回 Step 4 重新驗證；不得退回 `executionOrder`。

#### `UNSERVED_SERVICE_PULSE` · error · limit

某個完整交路起班脈衝在下一脈衝前沒有可用車承接。報告會列出秒數與時段；該處實際 PPHPD 會低於目標，不再靜默漏班。

---

### 3.2 展開與占用（`expand`）

#### `NO_ROUTE_FOR_TASK_TYPE` · error · actionable

| 項目 | 說明 |
|------|------|
| **何時** | 正線任務找不到可指派路線 |
| **根因** | Step 4 未配置對應任務類型之路線，或輪替／鎖定後可用集合為空 |
| **處置方向** | 補齊路線群組與執行／鎖定組合 |

#### `MISSING_TRAVEL_TIME` · error · actionable

| 項目 | 說明 |
|------|------|
| **何時** | 無法計算有效占用（缺行駛時間或缺站停靠） |
| **根因** | 路線缺 min／avg 行駛，或停靠秒數不完整，導致無法估占用長度 |
| **處置方向** | Step 4 補行駛與停靠；必要時回地圖補 leg |

#### `STATION_LEG_TRAVEL_INVALID` · error · actionable

| 項目 | 說明 |
|------|------|
| **何時** | 站間 leg 資料非法 |
| **根因** | 負值、缺欄，或 min＞avg 等不變量被破壞 |
| **處置方向** | 修正地圖／目錄烘焙之 leg 後重新載入路線 |

#### `STATION_LEG_TRAVEL_INCOMPLETE` · warning · actionable

| 項目 | 說明 |
|------|------|
| **何時** | 部分站間 leg 缺失 |
| **根因** | 拓撲未覆蓋全線；引擎退回整線 avg／min 估算逐站時刻 |
| **營運解讀** | 班表仍可生成，但站間精度下降 |
| **處置方向** | 補齊 leg 以提高精度（非硬擋） |

#### `STATION_TIMING_INFEASIBLE` · error · actionable

班次卡無法同時容納完整停靠、各 leg 最快行駛與 10 秒到站對齊。引擎不截短末站停靠；須延長班次或修正 leg／停靠設定。

#### `ROUTE_SUCCESSOR_MISMATCH`／`ROUTE_STATION_DISCONTINUITY` · error · actionable

同車相鄰正線未依已驗證 instance successor，或前趟 terminal 不等於後趟 origin。典型錯誤如 TNB(P2)→NT(P1)、TSB(P3)→TS(T3)。

#### `CLOCK_ALIGN_VIOLATION` · error · actionable

| 項目 | 說明 |
|------|------|
| **何時** | 發車錨點或下一錨點未落在 10 秒格 |
| **根因** | 違反 S3 時鐘對齊契約（系統刻度為 10 秒） |
| **處置方向** | 將時刻對齊 10 秒倍數後再存／再生 |

#### `ANCHOR_CONFLICT` · error · limit

| 項目 | 說明 |
|------|------|
| **何時** | 本趟實際結束晚於下一模板發車錨點 |
| **根因** | 同車在下一服務錨點前無法結束本趟占用；時窗、停靠、恢復與列數無法同時滿足 |
| **營運解讀** | 屬多約束衝突下的極限，非單純「某一欄填錯」 |
| **處置方向** | 增加時間線列數、縮短停靠／恢復，或放寬正線視窗 |

於展開階段若同車相鄰正線空檔不足，亦可能在此路徑寫入恢復／換線相關錯誤（與 §3.4 語意一致）。

### 3.3 生成前折返時限（`validateTurnaroundLimits`）

#### `TURNAROUND_LIMIT_EXCEEDED` · error · actionable

| 項目 | 說明 |
|------|------|
| **何時** | **單一路線**「最快一圈＋最低恢復」＞ 車輛折返時限 |
| **根因** | 該線物理週期已超越時間模板推導之折返上限 |
| **處置方向** | 縮短該線行駛／停靠，或放寬折返時限 |

#### `ROUTE_ROTATION_OVER_TURNAROUND` · warning · limit

| 項目 | 說明 |
|------|------|
| **何時** | 多路線情境下，**鎖定全優先組合**（若已鎖定）之最快一輪秒數，或（未鎖定時）執行順序整輪加總 ＞ 折返時限 |
| **根因** | 與 Step 4「排班採用組合」看板同源之週期下限已超標；**不是**另算一筆無關的「全部路線亂加」 |
| **與 Step 4 關係** | 若 Step 4 已因超限而無法鎖定，理論上不應帶著過期鎖定進入生成；若仍見此警告，應核對指紋是否失效、或時限／參數是否於鎖定後變更 |
| **營運解讀** | 警示級：可繼續微調班表，但表示「鎖定組合物理上已緊／已超」 |
| **處置方向** | 回 Step 4 調整組合占用／換線／恢復，或放寬折返時限 |

### 3.4 計畫結構驗證（`validate`）

#### `TIMELINE_OVERLAP` · error · actionable

| 項目 | 說明 |
|------|------|
| **何時** | 同一時間線上兩非過渡區塊時間重疊 |
| **根因** | 手動拖移、生成缺陷，或例外重疊規則未涵蓋之衝突 |
| **例外** | 允許之調度／保養重疊、進場載客偷保養尾等受控重疊不計入 |
| **處置方向** | 調整或刪除衝突班次卡後重驗 |

#### `HEADWAY_PHYSICAL_IMPOSSIBLE` · error · actionable

| 項目 | 說明 |
|------|------|
| **何時** | 同方向相鄰發車間隔 ＜ 車隊物理可達班距下限 |
| **根因** | 下限 ≈ 單車最短週期／時間線列數（並對齊 10 秒）。列數不足或單車過長時，物理上無法維持該間隔 |
| **處置方向** | 增加 `scheduleRowCount`，或縮短該路線占用 |

#### `HEADWAY_BELOW_TARGET` · warning · limit

| 項目 | 說明 |
|------|------|
| **何時** | 同方向間隔低於時段目標班距，但仍高於物理下限 |
| **根因** | 跨時段時下限刻意取兩時段之**較嚴者**；實際對班常來自補完回程、掛車延後或多車擠班，而非理想脈衝 |
| **營運解讀** | 演算法在硬約束下的取捨結果，未必是設定「算錯」 |
| **處置方向** | 加列、略降恢復／換線、拉長整備讓渡；或接受該方向部分脈衝被略過 |

#### `INSUFFICIENT_TIMELINES` · warning · actionable

| 項目 | 說明 |
|------|------|
| **何時** | 以目標班距反推所需車數，高於目前時間線列數 |
| **根因** | 模板列數與尖峰班距不匹配；穩態班距將被迫偏大 |
| **處置方向** | 提高列數或放寬尖峰班距 |

#### `RECOVERY_INSUFFICIENT` · error · actionable

| 項目 | 說明 |
|------|------|
| **何時** | 同車兩正線之間空檔 ＜ 最低恢復時間（S1） |
| **根因** | 恢復為獨立可加項；空檔被占用長度與錨點擠壓 |
| **處置方向** | 加大空檔、略降 Step 4 最低恢復，或調整相鄰時刻 |

#### `ROUTE_SWITCH_BUFFER_INSUFFICIENT` · error · actionable

| 項目 | 說明 |
|------|------|
| **何時** | 換路線時空檔 ＜ 恢復 **＋** 前一路線換線緩衝（S2，相加不取 max） |
| **根因** | 換線緩衝與恢復是獨立成本；只滿足其中一項不足 |
| **處置方向** | 加大空檔，或調降前一路線換線緩衝／恢復 |

#### `ROTATION_CYCLE_INCOMPLETE` · error · limit

| 項目 | 說明 |
|------|------|
| **何時** | （驗證）正線趟數非輪替單位整數倍；或（補完）無法安全插入回程而撤未成輪去程 |
| **根因** | 車輛地理成輪是硬約束：寧可撤去程，也不硬塞違規回程或讓車停在對側終點 |
| **處置方向** | 加大整備切入餘裕、加列、略降恢復／換線，或放寬該時段班距 |

### 3.5 進場載客插入（`insertMaintenanceEntryServiceTrips`）

#### `MAINTENANCE_DISPATCH_UNREACHABLE` · warning · policy

| 項目 | 說明 |
|------|------|
| **何時** | 保養尾端無法插入安全的進場載客短交路 |
| **根因（兩類）** | ① 現有路線無法從出場站接到首班起點；② 尾巴時間不足，或插入會追上同路線上一班 |
| **策略語意** | **正線優先**：僅在「時間夠且不追班」時偷保養尾巴插入；插不進則略過，交後續輪替接手——**不是漏填欄位** |
| **介面常見文案** | 「略過『保養』後的進場載客——…」 |
| **處置方向** | 加長保養尾巴、拉開同路線前班間距，或調整首班起點／出場站對照 |

進場載客本身（例如代號 `NT1603`、色卡與正線不同）是**成功插入**的產物：計入運能、不算輪替；與本警告互斥出現於同一插入嘗試。

## 5. 解讀原則（給審閱者）

1. **先看 `kind`，再看 `severity`**：策略說明不必當「系統壞掉」；演算法極限優先檢討約束是否互相打架；可調整則回溯 Wizard 或班次卡。
2. **error 擋參數化完成；warning 要求知情繼續**：例如進場載客略過、組合略超折返時限。
3. **同一現象可能對應不同 code**：例如「空檔太短」在同線是 `RECOVERY_INSUFFICIENT`，換線是 `ROUTE_SWITCH_BUFFER_INSUFFICIENT`，對錨點是 `ANCHOR_CONFLICT`——根因層級不同。
4. **Step 4 鎖定與引擎折返警告應對齊同一套「排班採用組合」秒數**；若兩者敘事不一致，優先視為實作／指紋時序問題，而非營運自相矛盾。
